# 设计理由（历史）

> 这是这套系统一轮轮改过来的记录，留着备查。现在的规则以《基础》《组件》《模式》《取舍》四页为准；这里的旧说法，后面几轮改过的都标了注。

用第一性原理推导：先弄清官网和 App 分别要干什么，再区分哪些是“灵魂”、哪些只是“音量”。

## 1. 官网和 App 的任务不一样

|  | 官网 | App |
| --- | --- | --- |
| 看多久 | 一次，30 秒 | 每天几小时，几百次 |
| 主角 | 品牌自己 | 用户的对话、任务、agent |
| 目标 | 被记住、被转发 | 不打扰、不出错、不累 |
| 信息密度 | 低：一屏一个观点 | 高：一屏几十个元素 |

官网用音量换记忆点；App 要把音量还给内容。

## 2. brutal 风格放进 App 为什么显得“太大胆”

风格本身没有错，问题出在**品牌音量被平均分给了每一个元素**：

- **边线太密**：每个元素都有 2px 纯黑描边，一屏就有几十条高对比边线。全是噪音，眼睛找不到重点。
- **“可点感”通胀**：硬阴影的意思是“按我”。如果所有东西都有硬阴影，就等于没有东西能按。
- **饱和色面积太大**：大块的黄、粉、青放在营销页是惊喜，放在每天打开的工作台上是疲劳。
- **字在喊**：小标签全大写、加宽字距，是海报的语气；工作台上一屏几十个，读起来又慢又吵。
- **暗色模式失效**：黑描边和黑阴影在暗底上会直接消失，这套语言没法翻译成暗色，而暗色是主流 App 的标配。
- **新鲜感会衰减**：第一次看很酷，第一百次只剩吵。
- **平台习惯**：主流用户的肌肉记忆来自 iOS 和 Android。外壳越像系统，用户要学的就越少。

这也是官网 CSS 里早就存在一个 `elegant` 主题的原因。但它把灵魂也一起删掉了：灰线、系统字体、字母圆头像，谁都能接受，可 agent 没了像素脸，看起来和人一模一样，“agent 是有名字、有脸的队友”这个产品主张也就看不见了。

## 3. 什么是灵魂：拿掉以后就不像 Raft 的东西

1. **暖纸 + 墨黑**（`#fffaef` / `#141111`），而不是冷白和冷灰。（第五轮按产品代码换了位置：暖纸留在桌面侧栏，内容区是白的，见第 10 节。）
2. **两种声音**：Space Grotesk 是人的声音，Space Mono 是机器的声音。
3. **糖果色有分工**：黄 = 选中 / 品牌，粉 = 行动。官网产品截图里已经是这样用的。
4. **8×8 像素 agent**：把“agent 是有名字、有脸的队友”这个产品主张画出来。
5. **硬阴影**：贴纸感、可以按、手作感。
6. **千禧年网页聊天室的怀旧**（官网用户评价里的原话）：`#` 频道方块、As Task 勾选框、等宽字体的事件行。
7. **俏皮又直接的文案。**

## 4. 推导：灵魂全留，音量只花在有意义的地方

| 灵魂元素 | 官网 | App |
| --- | --- | --- |
| 墨线 | 所有东西都有 | 只给纸色控件的外框，让墨线重新代表“这是控件”；彩色贴纸保留墨边 |
| 硬阴影 | 所有东西都有 | 第一版只给主操作；第二版彻底从控件上拿掉，只留在品牌插画里（见第 7 节） |
| 糖果色 | 大面积 | 黄 = 你、粉 = 去做；另外几色是任务状态和状态灯的固定意思，小面积使用；agent 头像的底色跟着像素形象走（第 10 节） |
| 像素形象 | 装饰 + agent | agent 的脸（产品自己的 16 个形象，各带底色）+ 状态像素；靠脸（而不是形状）分清人和 agent |
| 黄色 | 顶栏、CTA 色带 | 外框（手机一级页顶栏、桌面 Rail），加上导航里的选中、你所在的频道、@你、搜索命中；提示（toast、tooltip）不用黄（第 11 节） |
| 直角 | 全部 | 像素家族（头像、频道块、状态点、徽标）接近直角；控件 8px、容器 10px、对话框 16px（官网的产品窗口本身就是 12px）；只有开关是圆的 |
| 全大写 | 小标签到处都是 | 只在引导页的步骤签上（音量 9） |
| 字体 | — | 不变：这是最便宜、覆盖面最广的品牌载体 |
| 文案 | — | 不变；幽默集中放在空状态和引导页 |

## 5. 音量表

| 场景 | 音量 | 可以用到 |
| --- | --- | --- |
| 频道、首页、任务、设置 | 5 | 黄色外框、一个粉色主操作、墨线控件、头像和状态灯这些小块颜色 |
| agent 主页 | 7 | 再加：大号像素贴纸、`shadow-sticker-lg`、漂浮 |
| 空状态、完成庆祝 | 8 | 再加：倾斜的贴纸组 |
| 引导页、App 内的营销页 | 9–10 | 再加：整屏黄色、半调网点、`text-hero`、全大写的小标签，基本照搬官网 |

同一个频道页放在这条刻度上看：音量 10 是把官网原样搬进来，每个元素都有 2px 墨框和硬阴影，状态签是饱和色块，第一眼最难忘，第一百眼最累；音量 1 是上面说的 `elegant`，安全但没有灵魂；本系统在 5。

## 6. 遇到新情况时，按顺序问这六个问题

1. 这是内容、分区还是控件？内容里用发丝线，分区之间用分区线，控件用墨线（第 11 节）。
2. 这一屏的主操作是什么？只有它是粉色按钮（粉色的未读数和提醒点说的是“等你处理”，不算按钮）。
3. 这个颜色在产品里是什么意思？先查产品代码和 raft-ui 的配色规则：它是身份（头像）、状态（任务状态、状态灯）、信号（你 / 去做 / 信息）还是后果（会打断 / 收不回）？都不是，就是装饰，去掉。提示（toast、tooltip）不属于其中任何一种，所以用中性色。
4. 这个元素在别处出现过吗？同一种元素只有一种样子；要例外，就把理由写进它的 README。
5. 关了灯（切到暗色模式）它还成立吗？
6. 第一百次看到它，用户会不会烦？

## 7. 第二轮：外框响，内容静

第一版把音量平均压到 4 以后，有两件事值得重新想。

**按钮的影子可以彻底拿掉。**硬阴影本来是为了说“按这里”，但到第一版时，“按这里”已经由三样东西同时在说：粉色填充、墨线描边、每屏只有一个。第四个信号是冗余的，冗余的代价有三笔：
- 暗色模式下黑影子本来就看不见，等于亮暗两套行为不一致；
- 按下时位移 2px 会让周围元素抖一下；
- 和品牌插画里的贴纸抢同一种语言。

拿掉以后，按下改成压暗一层（`sticker-pressed`）。硬阴影只留在插画里，反而更像“贴纸”。

**外框应该更响。**品牌音量花在哪里，成本不一样：
- 花在**要读的地方**（消息、卡片、按钮）会累人；
- 花在**不需要读的地方**（顶栏、Rail）几乎没有认知成本，但每屏都在、全时在线。

彩色顶栏在主流 App 里也很常见，用户不需要学习。所以把官网那条黄原样搬回顶栏和 Rail。这一笔让音量从 4 升到 5，而且升在对的地方。（当时下面还压了一条官网同款的 2px 墨线，第四轮换成了和别的分区一样的发丝线，见第 9 节。）

**外框变黄以后，“选中”需要重新想。**在黄色 Rail 上试过三种选中态：
- 墨块最醒目（墨对黄 13:1），但它会成为整屏最黑、最重的一块，旁边侧栏的选中又是黄贴纸，一黑一黄两套语言并排；
- 白底无框最柔和，但白对黄只有 1.4:1，扫一眼找不到自己在哪；
- 白贴纸（白底 + 1.5px 墨边）采用：和侧栏、分段控件里的黄色选中是同一种贴纸，只是换了颜色，也和官网黄色顶栏上那颗白色 EN 按钮一个语言。

暗色模式下外框是墨色，选中回到黄贴纸（第五轮后半改了：暗色外框和产品一样不用黄，选中亮成内容的颜色，见第 11 节）。第三轮又把它从只包图标扩大到包住整个 Rail 项（见第 8 节）。

**暗色模式下外框变成官网页脚。**整条黄色在暗色里是全屏最亮的东西，和暗色模式“降低亮度”的初衷相反。官网自己已经给了答案：页脚是墨底、黄 logo、黄字。（第五轮后半撤回了黄字和黄色选中，只留黄色的 mark：产品的暗色主题里外框完全不用黄，见第 11 节。）

**粉色：黑字，所以往淡里调。**Raft 的品牌色都是“浅糖果色 + 墨黑字”。白字要在粉上达到 4.5:1，粉得暗到 L≈58%，那已经是树莓红，会跳出这个家族，还会和 `red`、`danger` 撞色。既然用黑字，粉就该往淡里走：黑字的对比度只取决于粉有多亮。官网的粉在这套颜色里偏深，提到和薰衣草、橙、青同一档后，黑字从 7.8:1 升到 9.5:1，整套颜色也站齐了。比过的六个候选：

| 色号 | 是什么 | 相对亮度 | 黑字 | 白字 | 结论 |
| --- | --- | --- | --- | --- | --- |
| `#FE7DA8` | 官网原色 | 0.39 | 7.8:1 | 2.4:1 | 偏深：品牌色里只比珊瑚红亮 |
| `#FF99C3` | 现在的 `pink` | 0.48 | 9.5:1 | 2.0:1 | 采用：和 lavender / orange / cyan 同一档，饱和度仍到顶，色相微微偏冷，免得变淡后发橙 |
| `#FFA6C1` | 更淡 | 0.52 | 10.3:1 | 1.8:1 | 成了 pastel，不像“去做” |
| `#FF78B8` | 上一版 | 0.38 | 7.7:1 | 2.4:1 | 更鲜，但其实更深，方向错了 |
| `#FF5388` | 变种 | 0.29 | 6.1:1 | 3.1:1 | 更深，白字也不过线 |
| `#D71F75` | 白字需要的粉 | 0.17 | 3.9:1 | 4.8:1 | 已是树莓红，跳出糖果色家族 |

**圆角收紧一档**（控件 10 → 8，卡片 14 → 10）。拿掉一个“硬”的信号（阴影），就用另一个（更利落的角）补回一点，总音量才落在目标上。

### 从变种里借了什么，没借什么

借了：
- **成员计数**：`2H · 3A`（Space Mono），一眼看出频道里人和 agent 的比例。
- **证据条** `rf-proof`：agent 说“做完了”时附上 CI / commit / 快照，可以一键转成任务。agent 的话要可验证。
- **@ 委派 chip** `rf-mchips`：composer 里直接点名最近在干活的 agent。
- **侧栏里单独列出 agent**：每个 agent 带运行时（Claude Code / Codex / Hermes）。
- **调节器**这个想法：用来讨论音量很好用，讨论完把结论写回 tokens 和这一页（调节器本身已移到 `archived/`）。

没借：
- **消息做成一张张卡片**：一屏几十条就是几十个框。
- **emoji 图标**（💬 📋 ⚡ 🤖 ✅）：各平台渲染不一致，显得廉价，而且我们有 Lucide 和像素形象。
- **给 agent 用字母头像**：像素形象是 Raft 最能拥有的东西，换成字母等于换成任何一个 SaaS。
- **玫红配白字**：对比度 3.1:1，不过线。

## 8. 第三轮：同一种东西只有一种样子

这一轮的反馈背后是同一个原则：同一种元素在整套系统里只能有一种样子；要有例外，例外得有理由，并且写下来。

**头像都是方的。**之前用形状区分人和 agent（方 = agent，圆 = 人）。但 agent 的脸本来就是像素形象，人的脸是照片或首字母——内容已经说清了是谁，形状只是把这句话再说一遍，和第二轮里按钮的影子一样，是冗余信号。官网也是这么做的：团队介绍里，人的照片和 agent 的像素头像放在同一种黑框色块里。拿掉圆以后，所有身份（人、agent、频道）都是同一种方贴纸：同样的尺寸、圆角、墨边和身份色，只是脸不同。（第五轮改了两处：频道是一个地方，不是一个谁，所以是中性的 `#` 方块，不算身份；身份色交给像素形象自带的底色，见第 10 节。）

**圆只留给开关。**头像不圆了，剩下的圆就显得没有理由：计数徽标、Tab 指示器、运行时签、@ chip。它们各自归进已有的家族：徽标是“点”，和像素一样方；Tab 指示器是选中贴纸，和分段控件一样用 `radius-md`；签用 `radius-sm`。开关保留胶囊，那是平台约定，方的开关认不出来。

**黄和粉不当身份色。**黄和粉是信号，作用来自稀缺。“一屏一个粉”被粉色的频道标打破过：频道页顶栏里一块粉，底部发送键又是粉。黄色头像放在黄色选中行旁边，也会让人以为它被选中了。所以身份色只从六个分类色里选。官网上 XX 用粉底、DD 用黄底，App 里分别换成 `cyan` 和 `red`。（第五轮撤回了这一条：agent 头像的底色是产品像素形象自带的，可以是黄或粉；频道干脆没有颜色。当时担心的两件事都从别处解决了，见第 10 节。）

**选中贴纸盖住整个选项。**侧栏行、分段控件的选中都是整块贴纸，Rail 却只包住图标：同一种状态，两种范围。现在 Rail 的贴纸盖住图标和文字。手机 Tab 栏保留只包图标的小贴纸，这是写下来的例外：Tab 栏在纸面上、每屏都在、横跨全宽，整格贴黄等于在屏幕底部再造一条外框，和“外框只有一个”冲突；这也是 Android 用户熟悉的样子。

**全大写退场。**全大写是音量。它在海报上有用，在工作台上会让单词失去轮廓、读得更慢；中文没有大小写，中英混排时只有英文在喊；翻成别的语言也更难控制长度。现在层级只靠字号、字重和颜色，机器写的标签可以全小写（`agent`）。全大写只留在引导页的步骤签上，那里是音量 9，照搬官网。

**一张字阶。**组件里用到的每个字号现在都在 tokens 里：补上了一直在用的 15（按钮、名字）、13（分组标题、表单标签）和品牌时刻的 40；去掉了只为大写标签存在的 `mono-label`；时间戳统一成 12px 的 Space Mono，不再一处 11、一处 12。

**组件目录只放组件。**音量调节器、音量对比、粉色研究、Rail 选中态对比都是讨论用的页面，不是拿来搭界面的东西；放在组件目录里，使用者会把被否掉的方案当成可选项。结论写进了这一页（第 5、7 节），原页面移到 `archived/`。“外框”是一个概念，由两个组件实现，所以拆成 NavBar（手机顶栏）和 Rail（桌面）两张卡，旧的纸面导航行随之去掉。Raft mark 在外框里一律裸放，手机和桌面一样，不再有白色底块——它在黄外框上会被当成选中贴纸。

**再细一层：同一种东西只有一种尺寸。**改完以后又做了一次逐卡对照，把剩下的分叉也合上了：
- 导航行只有三种形态（一级页、二级页、主页类二级页），每个一级页都以工作区切换开头，新建一律是外框右上的粉色小按钮（任务页不再用悬浮按钮）；
- 单独的状态像素只有一个尺寸（9px、1.5px 边），签只有一个高度（22px）；头像上的状态灯跟着头像缩放（9 / 11 / 14 / 20px，99px 大头像上的边是 2px）；
- 黄色在黄外框上一律换成白：Rail 的选中、外框里的“需要你”像素（第五轮提醒点改成了粉，就不用再换白）；
- 勾上、打开、选中都是黄贴纸（开关不再用 lime，lime 只表示状态），也去掉了没人用的黄色按钮；（第五轮后半收窄了：勾上的复选框是墨，内容里的选中是青，见第 11 节）
- 头像状态点那道缝的颜色跟着所在的底走（纸或卡片），不再在暗色里留一圈黑边；
- 计数和 ID 一律用 Space Mono，出现在一句话里也一样；
- 所有能点的东西都有同一个焦点环，点击区不小于 44（第五轮后半补齐了开关、@ 委派 chip 和文字按钮；正文里的行内链接和引用 chip 跟着文字走，不补）。

## 9. 第四轮：分区之间只有一种线

外框和内容之间原来压着一条 2px 粗线（亮色是墨线，暗色是黄线），是从官网顶栏底下直接搬过来的。按这套系统自己的规则，它站不住：

- **它说错了话。**规则 2 说墨线 = 控件。顶栏下面那条墨线把整块外框说成了一个控件，可外框是一块区域，控件在它里面。
- **同一种东西有了两种样子。**App 里还有好几处分区边界：Rail 和侧栏、侧栏和正文、桌面标题栏和消息流、分段栏、Tab 栏，用的都是发丝线，只有外框用粗线。
- **它是冗余信号。**黄和纸的交界本身就是边界，粗线只是把这件事再说一遍，和第二轮的按钮影子、第三轮的圆头像一样。
- **暗色里它最亮。**暗色外框改成墨色，就是为了不让全屏最亮的东西钉在顶上；那条 2px 黄线却在顶上和左边各钉了一道。

现在所有分区之间都是同一种发丝线（`border-hairline` + `line`），外框也一样。`line` 是半透明的墨，叠在黄上是一道略深的黄，叠在纸上是浅灰，不需要单独的线色。线宽从三种减到两种：1px 给内容和分区，1.5px 给控件外框和贴纸的边；`border-frame`、`frame-rule` 两个 token 删掉了。外框的音量来自那块黄，不来自那条线，所以日常页面还是 5。（第五轮后半发现这条发丝线太淡，在黄上几乎看不见，分区线单独成了 `line-seam`，加深到 45%，见第 11 节。）

## 10. 第五轮：颜色按产品代码来

前四轮的颜色是从官网推出来的。官网是海报，产品才是每天用的那张工作台，每个颜色在产品代码里都有确切的用法；设计系统应该描述产品，而不是另起一套。这一轮逐个对照了 raft-source（网页端的亮色 brutal 主题、暗色 Elegant Dark 主题、组件代码和视觉测试）和它依赖的 raft-ui 0.5.52，也在本地把网页端跑起来看了真实的界面。字体不在这一轮的范围里，继续用官网的 Space Grotesk / Space Mono。

**主界面是白的，奶油色只在侧栏。**之前把官网的奶油色 `#fffaef` 当成了整个 App 的纸。产品里不是这样：亮色主题的 canvas 和 panel 都是白，奶油色只给桌面侧栏，代码注释写得很直白——“sidebar warm cream, main panel white”；手机没有侧栏，一律是白。这个分工本身说得通：
- 白是读得最久的地方：最亮、最中性，照片、代码、截图放上去都不偏色；
- 奶油色放在导航那一栏，正好接住外面那条黄：黄（外框）→ 奶油（侧栏）→ 白（内容），从外往里一层比一层安静，和“外框响，内容静”说的是同一件事。

所以 `paper` 改成白，新增 `sidebar`。暖纸没有丢，只是回到了它在产品里的位置。亮色里 `paper` 和 `surface` 都是白，卡片和分组列表靠发丝线分开；墨的几档换成产品的半透明墨（100 / 68 / 60 / 30%）。暗色照搬 Elegant Dark 的明度阶梯（`#0d0d0b` / `#141411` / `#242422` / `#32322f`）和三档前景色，不再是从官网页脚推出来的暖黑。（第五轮后半把内容底换成了产品会话区用的 `#1b1b19`，又补了弹层的 `#292927`，见第 11 节。）

**外框只在导航层。**产品手机端，Tab 根页的顶栏是黄的（状态栏的 theme-color 也是这条黄），进到频道、私信以后顶栏是白的；频道的标题旁只剩一块黄色的图标块，私信是对方的头像。这和桌面一致：Rail 是黄的，主区的标题栏是白的。频道是你读和写的地方，是内容，不是导航。所以二级页（频道、私信、主页）的顶栏换成白色的 `rf-header`；频道标题旁的频道块变成黄色位置块（`rf-chan--here`）：你在这里。

**黄 = 你，粉 = 去做，现在有了出处。**raft-ui 的配色规则把两种品牌色按角色分开：primary（黄）是“提示和交互的表达”——新消息提示、提醒徽标、选中的 Tab、焦点环；accent（粉）是“核心和重要的动作”——弹窗的确认、composer 的发送。还有两条禁令：不要因为黄是品牌色就拿它做按钮，不要把粉用在被动的指示上。这和第二轮自己推出来的分工基本是一回事。产品代码里有两处和这条规则不一致，这里各自做了决定：
- **选中用黄。**网页版侧栏的选中行是粉底加硬阴影。选中是“你在这”，按 raft-ui 的规则属于黄；产品手机端的 Tab、分段控件、开关也都是黄。这里统一成黄贴纸（在黄色外框里是白贴纸）。
- **未读用粉，跟产品的代码走。**raft-ui 把新消息提示和提醒徽标归给黄；网页端的提醒点组件却默认是粉，注释里明确写着普通未读不要改色：“brutal-pink is the canonical unread color”。这里跟着代码用粉，理由有两条。一是黄在产品里还是“忙”的状态灯（`status-busy` `#FFD440`），未读要是也黄，Tab 上一个黄点就分不清是“有事等你”还是“有人在干活”；提醒点组件的注释自己也说，提醒和状态是两种意思、两种默认色。二是未读等的是你去读、去批，离“去做”比离“你在这”更近。这是这套系统和 raft-ui 文字相反的两处之一（另一处是焦点环，见第 11 节），值得在 raft-ui 或产品代码里对齐一次。
- 因为未读也是粉，“一屏一个粉”收窄成“一屏一个粉色按钮”：粉色的数字和小点不会被当成按钮。

**状态是产品的两套固定颜色。**
- 任务状态五种：To do 橙、In progress 青、In review 紫、Done 绿、Closed 石灰。之前自己加的 Blocked（红）和 Needs you（黄）删掉了，产品的任务状态里没有这两档：卡住了是 agent 出错（状态灯）；需要你是一个粉色提醒点，加上那一行里的动作按钮。To do 从石灰换成橙，石灰留给 Closed。
- 状态灯四种：在线绿、忙黄、出错橙、离线石灰（第五轮后半补上了第五种：外部 agent 是青，见第 11 节）。忙的黄是一个单独的 token（`presence-busy`），不是 `yellow` 的别名：状态灯是红绿灯那样的固定语义，换皮肤时品牌黄可以变，它不该跟着变。
- 状态灯不闪。之前“正在干活”是一个 1.6s 慢闪的像素；产品专门去掉了这个动画，代码注释里写着原因：环境状态不做循环动画，一个无限循环的呼吸灯会让页面按屏幕刷新率一直出帧（量过：开着弹窗时 144fps、GPU 80%，停掉以后 2fps、3%）。一屏十几个头像一起闪也确实是噪音。会动的只剩 agent 正在写消息时的三个像素（`rf-typing`），它只出现几秒；干活干几分钟的状态只用静止的黄灯表示。（第五轮后半连这三个像素也去掉了：产品里没有“正在输入”，见第 11 节。）
- `red` 不再表示“卡住了”，只给危险操作：产品的删除按钮就是红底墨字。`stone` 换成产品的 `#c0b9b1`，比之前深一档，做状态色才看得见。

**身份色交给像素形象。**第三轮定过“黄和粉不当身份色”，并给每个 agent 手配了一种身份色。产品里不是这样：每个像素形象自带底色（robot 青、cat 黄、heart 粉……），换形象就换底色；人没有照片时一律是薰衣草紫；频道没有颜色。这一轮照产品来，撤回第三轮那一条。当时担心的两件事，现在都从别处解决了：
- 担心粉色频道标打破“一屏一个粉”——频道现在没有颜色，标题里的位置块是黄的；
- 担心黄色头像被当成“选中”——选中是一整行、一整段的贴纸，头像永远带一张脸，读起来是一幅画，不是一个状态。

头像也换成了产品自己的形象表：16 个，另有 2 个保留形象没收。官网上画过的九个形象逐格对过，和产品表里的九个一格不差，只是有四个换了名字：宝箱是 `crown`，机器人脸是 `skull`，沙漏小人是 `star`，宝石是 `diamond`。

**有意和产品不同的地方。**下面几处没有照搬代码，每一处都是因为照搬会违反这套系统已经写下的规则：

| 哪里 | 产品代码 | 这里 | 为什么 |
| --- | --- | --- | --- |
| 粉色 | `#FE7DA8` | `#FF99C3` | 第二轮：配黑字往淡里提到糖果色主带，黑字 7.8 → 9.5:1（第 7 节） |
| 侧栏选中行 | 粉底 + 硬阴影 | 黄贴纸 | 选中是“你在这”；raft-ui 自己的规则也把它归给黄 |
| 未读数的字 | 白字（2.4:1） | 墨字（9.5:1） | 彩色贴纸上一律墨字 |
| 离线灯 | Tailwind 的 gray-400 | `stone` | raft-ui 禁用 Tailwind 默认色板；`stone` 是色板里的中性色 |
| 危险文字 | `#F70720`（白上 4.2:1） | `#b5321a`（6.1:1） | 文字要过 4.5:1 |
| 状态灯、提醒点 | 圆点 | 方像素 | 规则 6：所有“点”都是像素 |
| 分区和控件 | 2px 墨线，按钮带硬阴影 | 1px 发丝线，没有硬阴影 | 第二、四轮：墨线 = 控件，硬阴影只给插画（第 11 节：分区线换成了单独的 `line-seam`） |
| 暗色外框 | 深色，不用黄 | `#0d0d0b` + 黄字 | 第二轮：暗色外框像官网页脚，品牌在暗色里也认得出（第 11 节撤回，现在和产品一样） |
| 开关的形状 | 亮色主题是方的 | 胶囊 | 第三轮：开关的样子是平台约定，方的认不出来；颜色和产品一样，打开是黄 |

token 的变化：`paper`、`surface`、`surface-sunken`、墨的几档、`line`、各个 `*-soft` 的暗色值（`lime-soft` 当时是推出来的，第 11 节换成了产品的值）、`stone`、`frame` 的暗色值换成产品的值；新增 `sidebar`、`attention`、`orange-soft`、`status-closed`、`presence-online` / `-busy` / `-error` / `-offline`；删掉 `status-blocked`、`status-attention`。每个 token 的说明里写了它在产品代码里对应的是谁。

## 11. 第五轮后半：从真实场景往回查

第五轮前半是逐个 token 对颜色。这一半换了方向：从产品里真实出现的界面往回查，看设计系统有没有覆盖、有没有说错。对照的是产品跨平台视觉测试里的 116 个场景（组件库、登录、会话、首页、任务、成员和 agent、设置），加上四块代码的逐项清点：外壳和导航、消息区、任务 / agent / 设置 / 登录、基础组件和 token。同时有三条直接的反馈：分区线太淡，提示用黄太重，预览在窄的地方被切掉。

**分区线：在发丝线和墨线之间。**第四轮把所有分区换成了 15% 的发丝线。理由没错（墨线 = 控件，黄和纸的交界本身就是边界），但看下来太淡：它在白上和黄上都只有 1.4:1，叠在黄上只是一道略深的黄，Rail 和侧栏、外框和内容像糊在一起。之前那条 2px 纯黑的问题也是真的：它是全屏最黑的线，眼睛先看到线，画面被切成一格一格。在两者之间试了几档，2 倍屏上并排比：

| 墨的浓度 | 白上 | 黄上 | 看起来 |
| --- | --- | --- | --- |
| 15%（第四轮） | 1.4:1 | 1.4:1 | 在黄上几乎看不见 |
| 30% | 2.0:1 | 1.9:1 | 看得见了，在黄上还是虚 |
| 40% | 2.6:1 | 2.5:1 | 清楚了，离 3:1 还差一点 |
| 45%（采用） | 3.0:1 | 2.8:1 | 在白上刚过 3:1（界面元素的对比度门槛）；叠在黄上是一道暗金，和黄融在一起 |
| 50% | 3.5:1 | 3.3:1 | 开始像画上去的线，离控件的墨线太近 |

采用的这一档单独成了 `line-seam`，暗色是 26% 的白（2.2–2.3:1）。现在三种线各说一件事：内容里的 `line`（15%）、分区之间的 `line-seam`（45%）、控件的 `line-strong`（墨，1.5px）。菜单和对话框的边也用分区线：它们浮在内容上面，本身就是一块区域。第四轮的结论不变，外框的音量来自那块黄，不来自线；变的只是这条线终于看得见了。

**提示不用黄。**产品亮色主题里 toast 和 tooltip 是黄底加 2px 墨框，信息提示条是浅黄。按这套系统自己的规则，这三处都不该是黄：
- 黄说的是“你”：你在哪、你选的、叫到你、你找的。一条“已发送”不是其中任何一种；它和导航里的选中、@你 用同一种颜色，就会和它们抢“你在这里”。
- 提示分量轻：几秒就消失，或者只在悬停时出现。用全系统最响的颜色说最轻的话，音量花错了地方。
- 产品自己有现成的答案：Elegant 主题的 toast 和 tooltip 是一块中性的深色浮层（`#252429` 底、`#f3f3f5` 字）。各平台的 tooltip 和 snackbar 也都长这样，用户不需要学。

所以新增了 `hud` / `on-hud` / `on-hud-2`：toast 和 tooltip 在两种主题里都是中性深色，字 13.9:1（暗色 11.6:1），配 `shadow-float`；信息提示条用信息色青。toast 里的像素和动作按钮照旧：像素的颜色说的是那件事的状态（新任务是待办的橙），不是提示本身。

**预览跟着宽度走。**参考屏本来就在卡片上声明了宽度，由查看器整体按比例缩小；出问题的是组件卡：两栏各写死 390px，加上外边距要 860 多 px，卡片比这窄的时候，右边被切掉，又不能横向滚动。现在：
- 组件卡的栏是自适应网格，每栏 320–390px，放不下就换行；手机条的宽度跟着卡片，最宽 390；
- 外边距跟着宽度收，窄的时候 12px，宽的时候 24px；
- 万一还放不下，页面可以横向滚动，内容不会丢。

每张卡都在 320、480、640、880 四个宽度下查过，没有一处溢出。

**选中分成三种。**之前所有“选中”都是黄，产品里不是：导航里的选中（Tab、分段控件、侧栏行）是黄；列表里打开的那一行是青色浅底（产品的 SurfaceListItem）；生效的筛选条件也是青；菜单里选中的选项只有一个勾；勾上的复选框是墨（产品的 CheckMarker）。这背后是同一件事：黄只说“你在哪”，内容里挑出来的那一项是一条信息，勾上的复选框是一个值。要是全用黄，列表里一打开就是一大片黄，和导航的选中抢。第三轮“勾上、打开、选中都是黄贴纸”那一条，收窄成“打开的开关和导航里的选中是黄”。

**暗色模式的外框跟产品一样中性。**第二轮让暗色外框像官网页脚，墨底黄字，选中是黄贴纸。产品的 Elegant Dark 里外框完全不用黄：`#0d0d0b` 底、浅色字，选中项亮成内容的颜色。暗色模式就是为了把亮度降下来，整条外框上的黄字和黄贴纸，正是那块最亮的地方。现在暗色外框只留一个黄色的 mark；贴纸（头像、粉色按钮、导航里的黄色选中）照旧不反色。暗色的内容底也从 `#141411` 换成了产品会话区用的 `#1b1b19`，比侧栏和外框亮一档，暗色里同样是内容比导航亮。

**对照场景以后补上的东西。**
- 新组件：Tooltip、Banner（提示条）、Dialog（对话框）、Menu（菜单、下拉、筛选条件）、Loading（进度条、骨架、像素转圈）。这几样产品里天天在用，设计系统里之前没有。
- 弹出来的面有了自己的一层（`popover`，暗色 `#292927`），代码块有了自己的底（`code`），对话框后面是 `scrim`。
- 后果分两档：会打断但能恢复的操作（停止 agent、离开频道、重置）是橙色按钮，收不回的（删除）是红色按钮，和产品一样。对话框的按钮写清楚后果和留下什么：“Delete agent / Keep Box”。
- 正文里的链接是蓝的（产品 blue-700 / blue-300），2px 下划线，悬停变粉；界面里的文字链接还是墨色。行内代码、代码块、引用、频道和线程的引用 chip、搜索命中，也都照产品定了样子。
- 提到你的标记是一个 @ 方块，不带数字，和产品一样：它说的是“有人叫到你”，点进去就是那一条。
- 外部 agent 有了自己的状态灯（青），状态灯从四种变成五种。
- 任务状态的暗色值、`lime-soft` 的暗色值换成 Elegant Dark 的值。
- 去掉了“正在输入”的三个跳动像素：产品里没有这个提示。agent 在干活时，头像上是一盏静止的黄灯，名字下一行写它在做什么（`rf-msg__status`）。工作界面里唯一循环的动画是加载时的像素转圈，等完立刻收起（品牌时刻的漂浮另算）。

**和 raft-ui 文字相反的地方有两处。**除了第 10 节讲的未读，还有焦点环：raft-ui 的配色规则说焦点环取 primary（黄），产品 index.css 里是墨色的 outline。这里两处都跟产品代码走，也都值得在 raft-ui 那边对齐一次。

**有意和产品不同的地方又多了几处**，每一处都是照搬会违反已经写下的规则。完整的表在系统说明“颜色”一节的末尾，这一轮新加的是：

| 哪里 | 产品代码 | 这里 | 为什么 |
| --- | --- | --- | --- |
| 提示（toast、tooltip、信息提示条） | 亮色主题黄底黑框、浅黄 | 中性 `hud`；信息条是青 | 黄 = 你；提示分量轻（见上） |
| 手机 Tab 栏的选中 | 整格黄 | 只包图标 | 第三轮：整格黄等于在屏幕底部再造一条外框 |
| 线程的新回复数 | 青 | 和别的未读一样是粉 | 一个意思一个颜色 |
| 状态签、运行时签 | 饱和色实底 + 墨框 | 浅底：状态签配一个像素，运行时签配一个图标 | 一屏十几个，饱和色只留一个像素那么大 |
| 对话框标题、分组标题、徽标 | 常用全大写 | 句首大写 | 规则 7：字不喊 |
| 暗色模式的控件 | Elegant 主题：淡色洗底的按钮和签、圆头像 | 贴纸照旧 | 粉按钮、方头像、墨字在两种主题里是同一个东西 |
| 没有照片的人 | 人形图标 | 首字母 | 首字母能认出是谁，人形图标只说“这是个人” |

token 的变化：新增 `line-seam`、`popover`、`hud`、`on-hud`、`on-hud-2`、`code`、`link`、`pink-soft`、`presence-external`；`paper` 的暗色值换成 `#1b1b19`；暗色外框一组（`on-frame`、`on-frame-2`、`frame-active`、`on-frame-active`、`frame-active-edge`、`frame-pressed`）换成中性；任务状态和 `lime-soft` 的暗色值换成产品的值；`shadow-float` 暗色的那圈边、`focus-ring` 暗色的间隙跟着新的底色走。
