1. 摘要

当前系统已经“事实上”形成了一台状态机，但这台状态机是隐式的、分散的：agents.status、live activity、Activity Log、daemon trace、ready reconcile 各自写一部分事实。结果是同一个 offline/Stopped 可能表示用户手动 Stop、daemon 升级、机器断线、runtime crash 或 ready reconcile 缺失，用户和工程师都需要手工拼接上下文。

RFC 建议把 lifecycle 改成一等 event pipeline：所有 user command、daemon lifecycle、runtime process、ready reconcile、migration control 都先写成 canonical lifecycle event envelope，再由 reducer 读取显式的 in-memory state snapshot 并生成 projection plan，然后投影出 DB status、authoritative wake eligibility、live activity、durable Activity Log 和 ScopeDB trace rows。 

canonical lifecycle event
  -> lifecycle reducer
  -> intent_state / machine_reachability / runtime_state / control_gate
  -> db_status / authoritative_wake_eligibility / live_activity / activity_log / trace projections

5. 设计原则

Event First

状态变化先表示为 canonical lifecycle event，再由 reducer 生成当前状态和投影。

Orthogonal State

manual_stopped、machine_unreachable、migration_pending、working 不是同一维度的互斥状态。

Projection, Not Truth

status、dot、Activity Log、trace 都是 projection，不是独立事实源。

Reason Required

任何停止/中断/离线都必须带 reason/source，不能只写 offline。

Observable Dedupe

dedupe 不能静默发生；ScopeDB 里要能看到 outcome=deduped。

Tracing Co-Design

lifecycle event identity、correlation、projection rows 必须和 ScopeDB 查询一起设计。

Authoritative Wake

delivery/lazy wake 只能读 reducer state snapshot / wake plan 或持久 wake eligibility projection，不能从 live cache 猜。

6. 核心概念

6.1 Canonical lifecycle event

当前 PR #1683 实现里，canonical lifecycle event 是 server handler 内构造的 typed envelope，用来描述 agent lifecycle 发生了什么。它不是新增的 durable DB event row，也不是可 replay 的 append-only ledger。

type LifecycleEvent = {
  lifecycleEventId: string;
  serverId: string;
  agentId: string;
  machineId?: string;
  launchId?: string;
  eventType: LifecycleEventType;
  actor: "human" | "agent" | "daemon" | "server" | "system";
  source: "web" | "api" | "daemon" | "ready_reconcile" | "runtime" | "scheduler" | "external_cli";
  reason: LifecycleReason;
  correlationId: string;
  idempotencyKey: string;
  occurredAt: string;
  attrs?: Record<string, string | number | boolean>; // low cardinality only
};
Identity separation: lifecycleEventId、correlationId、idempotencyKey 是 canonical lifecycle identity。traceId / spanId 是 tracing 系统的 observation identity，不能成为 lifecycle source of truth。

6.2 Lifecycle reducer

纯逻辑：输入 explicit state snapshot + lifecycle event，输出 projection plan。当前 snapshot 是内存对象，由现有 DB/cache/control-gate 信息即时组装，不单独持久化。

type AgentLifecycleStateSnapshot = {
  intentState: "running_allowed" | "manual_stopped" | "deleted";
  machineReachability: "reachable" | "degraded" | "unreachable" | "unknown";
  runtimeState: "not_running" | "starting" | "running_idle" | "working" | "thinking" | "interrupted" | "crashed" | "stalled";
  controlGate: "open" | "runtime_profile_migration" | "reset_window";
  dbStatus: "active" | "inactive" | "stopped"; // legacy physical projection/input
  resetMode: "restart" | "session" | "full" | null;
  machineId?: string | null;
  sessionId?: string | null;
  launchId?: string | null;
};
Important: 这四个维度是正交的，不是一个互斥 enum。manual_stopped + machine_unreachable、migration_pending + not_running、running_allowed + machine_unreachable + interrupted 都可能同时成立。Reducer 必须输出 tuple，再由 projection layer 组合成 dot、log、wake eligibility 和 legacy AgentStatus。

6.3 Authoritative state snapshot

用于 scheduling / wake / delivery 决策的 canonical state snapshot，不等同于 UI dot。当前实现用 AgentLifecycleStateSnapshot 在代码里显式表达这个 tuple；它由旧 agents.status、reset window、runtime profile migration gate、machine reachability、session/launch 信息组合而来。它不是新的 durable source of truth，也不能 replay；如果未来需要 replay/CAS，需要把这个 snapshot 加 version 后持久化。

6.4 Projections

  • DB status projection: 兼容现有 API/UI 的持久 status。
  • Wake eligibility projection: 当前是否允许 delivery lazy-wake/start agent。它是 delivery boundary 的 authoritative projection，不只是 trace row。
  • Live activity projection: dot/current label。
  • Durable Activity Log projection: 用户可读历史行，带 reason-aware label。
  • Trace projection: ScopeDB event/span，带稳定 join keys。

6.5 Correlation window

由同一个高层 incident 引起的一组 lifecycle events，例如 2026-05-12 06:01:08Z daemon upgrade 中断四个 agents。

6.6 Correlation ownership

每个 lifecycle producer 必须定义自己如何 mint 或 propagate correlationId。

ProducerCorrelationId owner规则

Daemon upgrade/restart/shutdownDaemon 优先；server 只做诊断 fallback正确性需要 explicit daemonSessionId、connectionEpoch、restartWindowId 在 daemon stop / ready / reconcile 链路传播。machineId + daemonVersion + coarseTimeBucket 只能作为 trace fallback，不能作为 durable dedupe correctness key。

8. 状态模型

状态模型不再是一个单一 enum，而是四个正交维度。这样可以表达多个事实同时成立，避免把优先级写死进一台过大的 state machine。PR #1683 在代码里定义 AgentLifecycleStateSnapshot 作为 in-memory reducer 输入边界；现有 DB/cache/control gate 只负责构造这个 snapshot。

intent_staterunning_allowed / manual_stopped / deleted决定 agent 是否允许被调度和 lazy wake。用户 Stop 是 intent，不是 runtime 或 machine reachability。

Dedupe identity rule: lifecycleEventId 是事件身份，不能作为 durable projection dedupe key。Dedupe key 必须来自 semantic operation/window：user request id / stop command id、restartWindowId、connectionEpoch + closeEventSeq、launchId、migrationKeyHash 等。否则 retry/replay 只会生成新的唯一 event，不能 dedupe 同一次操作。
兼容策略：现有 AgentStatus = active | inactive | stopped 继续作为 projection 存在，避免为了 lifecycle cutover 做大爆炸式 DB migration。但 delivery/wake boundary 不能只读这个 legacy field；它必须读 reducer state snapshot / wake plan 或 authoritative wake eligibility projection。

9.3 Wake payload / freshness seed

#proj-aiax 的 duplicate-reply 讨论要求 wake/resume 入口提供 freshness seed。这个不进入第一版 reducer，但属于 lifecycle event payload 的扩展 slot。

type WakePayloadFreshnessSeed = {
  target: string;                  // canonical reply/read target
  replyTarget?: string;             // canonical write target if different from delivery target
  lastSeenMsgId: string;            // server-known latest relevant msg at wake creation
  lastSeenSeq?: number;
  recentActivitySummary?: string;   // sanitized / compact
  pendingNoticeIds?: string[];
  sourceEventId: string;
};

后续 exit-side send --seen-up-to / needs_confirmation 应复用同一组 anchor 字段名和语义。Notice response 必须是 proof-producing：必须包含足够 agent 构造 --seen-up-to=<anchor> 的字段，而不是纯 UX warning。

Native daemon-managed agent 通过 wake event 获得这些字段；external slock-cli agent 应通过 slock message check envelope 获得同构字段。两条路径的 producer 不同，但入口 freshness contract 必须 functionally equivalent。

10. 并发模型

PR #1683 当前不是 event sourcing，也不是全局串行 event loop。每个 server handler / daemon ingress path 同步执行 adapter → reducer → projection writer，projection writer 直接写现有 DB/read model 和副作用。这个设计先把 lifecycle 语义边界收敛到单 reducer/writer，不同时引入 durable queue、per-agent sequence 或 replay store。

当前保证

  • 单次 projection plan 内部一致：reducer 看到一个显式 AgentLifecycleStateSnapshot 和一个 canonical event，输出一组 DB status、wake eligibility、live activity、Activity Log、side-effect plan；writer 按这个 plan 执行，不再在旧 orchestrator 分支里重新判断产品语义。
  • DB 原子写和唯一约束：Activity Log projection 依赖 (agent_id, dedupe_key) partial unique index 做用户可见日志幂等。重复 ready reconcile / restart-window projection 会走 conflict/deduped，而不是追加多条相同日志。
  • wake/start 局部锁：现有 wake lock / launch guard 继续防止多个 replica 同时 wake/start 同一 agent；reducer 统一 wake eligibility 语义，但不替代这些锁。
  • reset / runtime-profile gate：delivery 和 routed delivery 都通过 reducer-owned wake plan 判断 reset_window / runtime_profile_migration，因此 projection trace 与真实 suppress 行为一致。
  • cross-replica routing：消息投递仍使用现有 owner/routed inbox 机制；lifecycle reducer 不改变 machine ownership routing，只统一状态/wake 语义。

明确不保证

  • 不保证 per-agent total order：两个 server handler 可以并发处理同一 agent 的 daemon activity、manual stop、ready reconcile。当前没有一条全局 per-agent queue 把所有 lifecycle event 串行化。
  • 不保证 event replay：ScopeDB trace 和 Activity Log 是 projection/observability，不是 durable lifecycle event store。不能从它们重建完整 reducer state。
  • 不保证 CAS/version 推进：AgentLifecycleStateSnapshot 不是带 version 的 persisted state row。agents.status 等 read model 仍可能在并发窗口里 last-write-wins；关键用户可见日志靠 dedupe key 幂等，而不是靠完整状态版本。
  • 不保证所有旧 transient race 消失：本 PR 把语义出口统一起来，降低分叉和重复投影；它不是完整的 concurrency model replacement。
未来增强：如果后续需要强并发语义，应引入 durable agent_lifecycle_events table / event stream，或持久化带 version 的 agent_lifecycle_state 并用 CAS/transaction 推进 projection。不要把 ScopeDB trace row、Activity Log row 或 live activity cache 误当成 replayable source of truth。

11. Tracing Contract

Tracing 是设计约束，不是事后补字段。lifecycle state snapshot、projection 和 ScopeDB 必须用同一组 correlation / idempotency / dedupe 描述同一批事实。

11.1 必要 invariants

  • 每个 canonical lifecycle event 都 emit 一个 trace event/span，并携带 lifecycle_event_id、event_type、agent_id、machine_id、reason、source、correlation_id、idempotency_key。
  • 同一个 incident window 内，server reducer/projection spans 和 daemon/runtime spans 必须共享 correlation_id。
  • correlation_id 用来 join incident；idempotency_key 用来表达 event ingest/retry 幂等；durable projection dedupe 另用 dedupe_key，不能混用。
  • Projection writes 必须携带 lifecycle_event_id 或 correlation_id，让 Activity Log row 能 join 回 canonical event。
  • Dedupe 必须可观察：duplicate reconcile attempt emit outcome=deduped 或 projection_skipped_reason=duplicate。
  • Trace attrs 必须 sanitized。agent_id、machine_id、launch_id 是 join-only internal ids，不是 dashboard aggregate dimensions。

12. Rollout 查询

下面是伪查询形状，用来确保 rollout 后不是只能靠文字解释，而是可以在 ScopeDB 中验证。

12.1 Daemon upgrade dedupe

-- For one daemon upgrade/restart window:
SELECT correlation_id, agent_id,
       count_if(event_type = 'runtime_interrupted') AS interrupted_events,
       count_if(projection_kind = 'activity_log' AND outcome = 'applied') AS durable_rows,
       count_if(outcome = 'deduped') AS deduped_attempts
FROM lifecycle_trace_view
WHERE correlation_id = :window
GROUP BY correlation_id, agent_id;

-- Assertion: durable_rows <= interrupted_events per agent,
-- and repeated ready reconcile attempts show up as deduped_attempts.

12.2 Manual stop no-lazy-wake projection

SELECT lifecycle_event_id, agent_id,
       intent_state, machine_reachability, runtime_state, control_gate,
       wake_eligibility, wake_block_reason, label_kind
FROM lifecycle_projection_events
WHERE event_type = 'manual_stop_requested'
  AND reason = 'user_stop'
ORDER BY occurred_at DESC
LIMIT 20;

-- Assertion: intent_state='manual_stopped',
-- wake_eligibility=false and wake_block_reason='manual_stopped',
-- label_kind='stopped',
-- no wake event applies until manual_start_requested.

12.3 Migration pending 不应投影成普通 Idle

SELECT lifecycle_event_id, projection_kind, outcome, label_kind, activity, detail_kind
FROM lifecycle_projection_events
WHERE event_type = 'control_state_changed'
  AND reason = 'runtime_profile_migration'
ORDER BY occurred_at DESC
LIMIT 50;

-- Assertion: migration pending projects as migration/control state,
-- not ordinary live_activity online/Idle while inbox delivery is gated.

13. External Agent Projection

新 roadmap 下，second-tier agents 更可能通过 public slock-cli 自接入，而不是作为 daemon-managed runtime driver。RFC 不能强行让 external agent 假装有 daemon process lifecycle；但 #proj-aiax 的 Work Inbox / post-action nudge 仍需要一个可比较的 projected agent state。

External slock-cli agent 的 identity/profile 是 launch-time contract：一个 external process 在其生命周期内代表一个 Slock agent identity。Slock 不能假设可以在运行中注入环境变量、system prompt 或 transient notice；动态 notice 必须通过 CLI pull surface 暴露，静态规则应通过 integration SKILL.md / guide 交给第三方 runtime。

Projection 等价不等于 producer 等价。Native runtime 的 facts 来自 daemon/process；external agent 的 facts 来自 public surface。AX 层只消费同一套 projection schema，不能假设所有 agent 都有 process-level lifecycle。

13.1 External notice / instruction limitations

  • Static instruction: public integration 应提供 versioned SKILL.md / guide，内容包括 thread etiquette、message/task commands、freshness policy、notice check 习惯。Skill 是 slock-cli contract 的一部分，需要跟随 CLI semantic version、兼容窗口和 deprecation policy；第三方 adapter 可以 pin 版本，并在不兼容时 fail loud。
  • Dynamic notice: daemon release notice、runtime profile notice、policy notice、pending migration 不能依赖 push 注入。CLI 需要一个 pull surface，例如 slock notices pending 或并入 slock message check。
  • Notice ack: 某些 notice ack 有 server-side 副作用，例如 runtime profile migration ack 会解锁后续 delivery。External surface 必须提供 slock notices ack <id> 等价写路径；daemon-managed tool ack 和 external CLI ack 必须投影为同一个 lifecycle event，而不是两套独立状态。
  • Envelope hints: slock message check 的返回 envelope 应 mirror wake payload 字段，例如 reply_target、last_seen_msg_id、last_seen_seq、pending_notice_ids。Native 用 push wake，external 用 pull envelope，但 agent 看到的 freshness/context shape 应保持等价。
  • Self diagnosis: slock agent whoami / slock doctor 应显示 profile、agent、server、scopes、credential expiry、contract version、pending notices。

15. 当前落地与后续迁移

PR #1683 current state: 这已经不是只定义 envelope 或只补 observability 的早期草案。当前实现把 start path、daemon activity ingest、manual stop/start、ready reconcile、machine disconnect、runtime profile gate 和 delivery wake plan 收敛到 adapter → reducer → projection writer 路径。Legacy 输入仍被兼容，但只停留在 adapter 层；lifecycle 产品语义必须由 reducer 决定，status/activity/log/wake 副作用必须由 projection writer 写出。

已完成的 cutover 边界

  • Event/envelope layer: agentLifecycleEvents.ts 定义 canonical event / projection trace envelope、identity、sanitized attrs 和 reserved attrs。它不做 reducer 语义，不写 DB，也不翻译 legacy daemon/server 信号。
  • Legacy adapter: 老 daemon/server 信号先进 legacyAgentLifecycleAdapter，转成 canonical lifecycle events。旧协议兼容集中在这里，不能散回 orchestrator 分支。
  • Reducer: agentLifecycleReducer 是 lifecycle semantic boundary，集中决定 DB status、wake eligibility、live activity、Activity Log projection 和 side-effect plan。
  • Projection writer: agentLifecycleProjectionWriter 是唯一输出 seam，统一写 DB status、live activity、durable Activity Log、wake projection trace、wake lock / launch guard / stop side effects。
  • Wake boundary: delivery 和 routed delivery 通过 reducer-owned wake plan 判断是否可唤醒；reset window 显式投影为 wake_eligibility=false + wake_block_reason=reset_window，与真实 delivery suppress-reset 行为一致。
  • Activity dedupe: durable Activity Log projection 使用 nullable dedupe_key 和 per-agent partial unique index 做语义去重；它不是 lifecycle event id、trace id、request id 或 correlation id。

兼容层保留

  • 现有 agents.status 继续作为兼容 projection 存在；读/写语义由 reducer/writer 统一维护，而不是让旧 orchestrator 分支各自决定。
  • 当前没有新增持久化 lifecycle events 表。Canonical event 是 in-process envelope；state 是 in-memory AgentLifecycleStateSnapshot；structured trace/projection contract 只用于观测和 rollout 验证。如果未来需要 durable event ledger，必须沿用本 RFC 的 identity/correlation/dedupe 边界，而不是把 Activity Log 或 trace row 当 event store。
  • daemon 老协议仍可输入：agent:status、agent:activity、ready reconcile、manual controls 等先经 adapter 映射。新 daemon 可以补更精确字段，但 server reducer 必须兼容老 daemon。

Merge / rollout gate

  • 这是 server lifecycle source-of-truth 重构，不是普通 helper PR。Code review no-blocker 只表示实现/contract review 通过，不等于可 merge。
  • PR #1683 必须等 @xxchan / @tygg 显式 merge gate 后才能进入 staging；不能仅凭 CI 绿和 reviewer no-blocker 直接合。
  • 合入后用本 RFC 的 acceptance cases 和 ScopeDB rollout queries 验证真实投影，不允许靠手工拼 Activity Log、daemon trace、server reconcile 来判断状态。

后续 UI / Product cleanup

  • 用户可见 labels：Stopped、Sleeping/Available、Running、Working、Interrupted、Disconnected、Migration pending。
  • tooltip 包含 reason/source，例如 Interrupted by daemon upgrade。
  • Profile Activity 不直接渲染 raw offline。

后续 Advanced AX hooks

  • Task post-action nudge 和未来 Agent Inbox handled/read 语义应接入 lifecycle producer/reducer contract；如果需要 durable stream，必须先实现真正的 event ledger，而不是另造 parallel ack model。
  • 第三方 agent 如果通过 public slock-cli 接入，也需要能产生/暴露足够 lifecycle events，否则 AX 行为会断层。

17. Open Decisions

  • intent_state=running_allowed + runtime_state=not_running + machine_reachability=reachable 应显示绿点、灰点，还是独立 sleeping indicator？这是产品决定。
  • daemon upgrade interruption 后 DB projection 保持 active 还是变 inactive？取决于 lazy-wake recovery contract 和 machine 是否已恢复。
  • Activity Log 中 daemon upgrade 是显示一条 machine-level row，还是每个 affected agent 一条 row？当前建议：先保持 per-agent row，但必须能 join 到同一个 machine incident correlation。
  • 未来是否需要持久化 lifecycle event ledger？当前 #1683 不新增 event 表；canonical event 作为 typed envelope + structured trace/projection contract 使用。若后续上表，必须保留本 RFC 的 event identity、correlation、projection dedupe 分层。
  • 未来 Agent Inbox 的 acted/read/handled 语义如何消费 lifecycle events？先 defer，不要另造 parallel ack state。

18. 建议

  1. 按 PR #1683 的新老分离边界继续 review：legacy adapter 只做输入转换，reducer 是唯一语义层，projection writer 是唯一输出层。
  2. 不要把 lifecycle 产品语义重新写回 AgentOrchestrator 分支；如果出现新 daemon/server 输入，先加 adapter，再让 reducer 产出 projection plan。
  3. 在新的 Agent Inbox / external agent / attested send 设计里，不要各自发明 parallel ack/handled/lifecycle 概念；需要状态转换时接入本 lifecycle model。
  4. 用上面的 acceptance cases 作为 regression tests 和 ScopeDB rollout queries；合入 staging 需要显式 human merge gate。
