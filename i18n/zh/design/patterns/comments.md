# 评论

人们评论文档，是为了讨论其中的某一段，所以评论应该放在那一段旁边。在文档查看器里，评论放在右侧页边，每张卡片与它所评论的段落对齐，那一段会被高亮。没有空间放页边时，段落旁边的一个标记会在底部面板里打开讨论。Google Docs、飞书文档和 Word 都是这样显示评论的；人们已经熟悉，所以 Raft 不另搞一套。

## 适用范围 {#when-it-applies}

Raft 自己渲染的文档上的评论：文件查看器里的 Markdown、文本或代码文件（[由现有部件组成](../components/overview.md#file-viewer)），以及以后的任何文档界面。不包括对消息的回复，那是消息列（[会话](./conversation.md#threads)）；也不包括 Raft 无法测量内容的文件，比如沙盒 frame 里的页面。

## 结构 {#structure}

```example
comment/compositions/margin
```

- 文档，然后是它右侧的页边：一个由 `CommentCard` 组成的 [CommentMargin](../../packages/ui/src/components/comment/comment.md)，每个 `CommentMarginItem` 放在它那一段的顶部。
- 每张卡片里是评论（[CommentEntry](../../packages/ui/src/components/comment/comment.md#anatomy)），收起时有一行回复数，展开时有回复框（[Composer](../../packages/ui/src/components/composer/composer.md)）。
- 文档里，被评论的段落高亮显示，但不改动文档的 DOM（[高亮](../../packages/ui/src/components/comment/comment.md#highlights)）。

## 规则 {#rules}

- 没有评论的地方什么都不显示：没有空页边、没有占位、没有标记。人们是来读文档的。
- 每张卡片与它那一段的第一行对齐，让视线能从文字直接横移到对它的评论。两张卡片会重叠时，下面那张往下移；卡片从不互相遮挡。
- 每段被评论的文字用浅黄色高亮（`brand` 叠在页面上，浅色模式 35%，深色模式 22%，加 `brand` 下划线）；当前打开的讨论所对应的段落用全黄色加墨色文字：打开的讨论是这个人选中的，而黄色表示你选中的东西（[颜色](../foundations/color.md#meanings-of-color)）。
- 一次只打开一个讨论。它的卡片加上墨色边框并从页边浮起（`shadow-float`），仍然与它的段落对齐，其他卡片给它让开位置。打开的卡片是人们阅读和输入的地方；其他卡片是一份列表，告诉人还有哪里可以读。
- 收起的卡片显示第一条评论（截到 2 行）和回复数。展开后显示所有评论和回复框。页边如果都是完整的讨论，每张卡片都会被推得离它的段落很远。
- 针对整篇文档的评论放在页边顶部，只放一次，并用一行文字说明。不要在每张卡片上重复文件名：查看器已经显示了。
- 找不到对应段落的评论（文档在它下面改了）也放在页边顶部，用一行文字说明（"Position not found"）。永远不要丢掉它，也永远不要把它挂到现在那个位置上的文字上：这条评论仍然是讨论的一部分，挂错了位置，就等于说了一句没人说过的话。
- 在打开的卡片里的 [Composer](../../packages/ui/src/components/composer/composer.md) 回复，用粉色的发送按钮：只有打开的卡片有发送按钮，所以它是这个界面上唯一的粉色按钮。
- 按 Esc 或打开另一张卡片，关闭当前打开的卡片。

## 发起评论 {#starting-a-comment}

在阅读的地方发起评论；在有人想评论之前，界面上不放评论控件（「没有评论的地方什么都不显示」）。

- 针对一段文字：选中文字后，页边出现一个 Comment 按钮，与选区对齐，和 Google Docs 一样。它在原位打开一张新卡片，回复框获得焦点；选区变成打开状态的高亮，其他卡片给它让开位置，按 Esc 或 Cancel 丢弃这张卡片。第一条评论之前没有页边，所以按钮浮在文档的右边缘，文档只在卡片打开时才让出空间：选中文字永远不会让鼠标指针下的文字移动。
- 针对整篇文档：文档还没有评论时，查看器的 Comments 按钮发起一条评论，放在页边顶部。有了评论之后，这个按钮用来显示和隐藏评论，页边顶部提供 Comment on File，直到出现针对整篇文档的讨论；之后就在那个讨论里回复。按钮的名字要符合它的作用：只有在它是开关时才是开关。
- 锚点暂时还无法定位的选区，变成针对整篇文档的评论，卡片上说明这一点，而不是不显示按钮：人们应该总能对正在读的东西说点什么。
- 在窄布局里，选区上同样的 Comment 按钮打开底部面板，标记列的顶部提供 Comment on File。
- 用键盘时，⌘⌥M（Ctrl+Alt+M，Google Docs 的快捷键）评论选区，这样用 Shift 加方向键选择文字的人永远不用离开文字。Comment 按钮也保留在 Tab 顺序里，排在文档之后，工具提示里显示快捷键。

## 宽屏和窄屏 {#wide-and-narrow}

根据文档能让出的空间，评论有三种形式：文档旁边页边里的卡片；文档旁边的标记，点开是底部面板；页面一点宽度都让不出来时，页面里的标记，点开是浮动卡片。

页边需要文档旁边有 304px：280px 的卡片列，加上它和文档之间 24px。只在文档还能保留至少 480px（每行约 60 个字符）时显示页边，也就是查看器宽 784px 起；并且只在桌面端显示：用鼠标或触控板、宽度 768px 起，这是所有桌面端尺寸的条件（[间距](../foundations/spacing.md#hit-targets)）。用触屏操作的平板不论多宽都用标记，和手机一样。

测量的是查看器，不是窗口：查看器旁边可能有侧栏或消息列（[响应式布局](./responsive.md#when-a-row-runs-out-of-room)）。卡片和标记是两种不同的结构，不是同一个结构换了样式，所以查看器用 JavaScript 测量自己的宽度，用 [`useCommentMarginFits`](../../packages/ui/src/components/comment/comment.md#wide-and-narrow)，而不是用容器查询。

```example
comment/compositions/viewer
```

- 页边放不下时，把卡片换成每段被评论文字旁边的一个 `CommentMarker`：作者的头像（最多 3 个）和数量。挤到 280px 以下的卡片每一行都会换行，而盖在文档上的卡片会遮住它所评论的文字。
- 点按标记，在底部面板里打开讨论（[Drawer](../../packages/ui/src/components/drawer/drawer.md)）：其中的评论、回复框，以及一个关闭按钮。面板打开期间，段落保持高亮。
- 窄布局里同样保留段落高亮、针对整篇文档的评论（顶部的一个标记），以及位置丢失的评论（在顶部那个标记的面板里，放在一行说明文字下方）。

```example
comment/compositions/marker-sheet
```

### 一点宽度都让不出来的页面 {#a-page-that-cant-give-up-any-width}

有些文档无法为页边或标记列让位：全宽的 HTML 页面或画布，让位就会在右侧被截掉。这时让页面保持自己的宽度，把标记放进页面里：

- 在每段被评论的文字上显示一个标记，放在页面里，显示它那个讨论里的评论数，和窄布局里 `CommentMarker` 的计数方式一样。不显示这个讨论在页面上的序号："3" 两种意思都能读，而且插入一个讨论会让后面的全部重新编号。
- 点击标记，它的讨论以浮动卡片的形式在标记旁边打开：处于活动状态的 `CommentCard`，包含所有评论和回复框。按 Esc、点击外部，或把标记滚出视野都会关闭它；页面滚动时它随标记移动。Figma 就是这样显示评论图钉的。
- 在触屏上，标记打开底部面板，和窄布局一样。
- 保留高亮。产品如果有一份所有评论的列表，在这种布局里它就是唯一的列表；在页边布局里，页边本身就是列表，所以不要同时打开两者。
