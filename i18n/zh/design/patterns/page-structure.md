# 页面结构

每个 Raft 屏幕都由同样的区域组成，所以熟悉一个产品的人，到了下一个产品也知道东西在哪里。在手机上，一个页面要么是带标签栏的一级页面，要么是盖住标签栏的推入页面。在桌面端，网页顶栏横跨顶部，下面的区域从左到右依次是：导航条、侧栏、主区域，以及打开时的侧面板。颜色从外往里逐级减弱，两个区域之间始终只有一条线。

## 适用范围 {#when-it-applies}

所有 Raft 产品的所有屏幕。一个产品有哪些目的地、每个屏幕显示什么，写在产品自己的页面上（[Raft Chat](../products/raft-chat/README.md)）。区域如何随宽度变化，见[响应式布局](./responsive.md)。

## 结构 {#structure}

### 手机 {#phone}

| 页面 | 顶部 | 中部 | 底部 |
| --- | --- | --- | --- |
| 一级页面：标签栏上的一个目的地 | 标签头部，在黄色外框上：先是状态栏，然后是一行 56px 的导航行（`PanelSectionHeader`），下面有一条接缝线。页面名称用 `text-headline`，从 16px 边距开始，下面最多一行副标题（数量用 Space Mono），两者作为一组在这一行里居中；末尾最多一个图标按钮。有筛选条件的页面把它们放在下面的一行里，在纸面上，下方有接缝线 | 直接放在纸面上的列表，或内嵌分组 | 标签栏（[MobileNav](../../packages/ui/src/components/mobile-nav/mobile-nav.md)） |
| 推入页面 | 页面头部：白色顶栏，56px，下面有一条接缝线（`PanelHeader`，[Panel](../../packages/ui/src/components/panel/panel.md)）：返回（44px 点击区域）、标题和可选的副标题，右侧最多两个图标按钮，用于本页面的操作 | 内容 | 能发消息的页面放消息输入框；其他页面什么都不放，因为页面盖住了标签栏 |
| 浮层 | — | 菜单（长按，对某一项进行操作）、选择列表（选一个值）、弹出层（一个短列表，比如 Working now、通知或服务器列表）、对话框（确认）、底部面板（一段简短说明，比如把 Raft 添加到主屏幕） | 不变：浮层不改动标签栏 |

- 每个手机页面都属于这两种之一，没有第三种（[导航](./navigation.md#going-back)）。一个目的地的第一个页面是一级页面。从页面里打开的所有东西都是推入页面：频道、私信、消息列、任务详情、从服务器标签打开的服务器页面（成员、计算机、设置）、个人资料、设置页、从搜索结果打开的任何东西，以及功能前面的门槛页。
- 所有一级页面的顶部都一样：56px 的导航行，上下除了筛选行不放别的东西。不用大标题，名称前也不放图标图块：标签栏已经显示了页面的图标（处于选中状态），而在手机上，大标题占的 53px 应该留给内容。由 stdrc 和 artin 于 2026-10-21 确定；移动应用和手机网页相同。
- 每个一级页面的导航行下方都画接缝线，不管有没有筛选行，这样所有一级页面的顶部都一致。
- 导航行和筛选行一起固定，内容在它们下面滚动。筛选行里放什么，由页面自己决定。
- 用顶部的颜色说明页面的种类：一级页面是黄色（深色模式下是外框的深色层），推入页面是白色（深色模式下是页面的背景色）。黄色表示人在一个标签的根部，白色表示人已经进入了一个页面。
- 两种顶部都用 Raft 自己的部件绘制，在手机网页、iOS 和 Android 上一样，不要用平台的导航栏（[导航](./navigation.md#what-each-platform-draws)）。不用大标题是 Raft 的规则，不管平台默认是什么。
- 在第一个一级页面上，服务器切换器占据名称的位置，铃铛放在末尾。其他一级页面上都不放铃铛和工作摘要。
- 在「搜索」标签上，搜索框占据导航行里名称的位置：距两侧各 16px，开头是搜索图标，有文字后末尾出现清除按钮（[InputGroup](../../packages/ui/src/components/input-group/input-group.md)）。它的筛选条件和其他页面一样放在筛选行里。它的行为见[导航](./navigation.md#search-on-a-phone)。
- 在推入页面的标题前，频道可以显示它的位置图块，私信可以显示对方的头像。顶部是搜索框的页面两者都不显示。
- 页面一打开就显示名称和副标题；不要等列表滚动后才显示。
- 页面的名称是它唯一的一级标题。在第一个页面和「搜索」上，名称的位置被切换器或搜索框占据，要给页面一个视觉上隐藏、写着页面名称的一级标题。
- 让状态栏和浏览器的主题色跟随顶部：一级页面用外框色，推入页面用纸面色，这样页面一直延伸到屏幕顶边。

```example
app-shell/compositions/mobile-root
```

### 桌面端 {#desktop}

最上面是网页顶栏，下面从左到右：

1. 导航条（[AppRail](../../packages/ui/src/components/app-rail/app-rail.md)）：黄色，只有图标。
2. 侧栏（[Sidebar](../../packages/ui/src/components/sidebar/sidebar.md)）：奶油色，可调整宽度。
3. 主区域：白色，有面板头部和内容（[Panel](../../packages/ui/src/components/panel/panel.md)）。
4. 侧面板，打开时出现。

各区域的宽度见[间距](../foundations/spacing.md#layout-widths)。

```example
app-shell/compositions/responsive
```

#### 网页顶栏 {#the-web-top-bar}

网页应用从 768px 起，在导航条上方加一条外框色的顶栏，中间是搜索。它是外框的一部分，不是内容，所以和导航条一样是黄色，黄色依然只用在外框上。桌面应用的标题栏就是这条栏，在任何宽度下都一样。

```example
app-shell/compositions/web-top-bar
```

- 高 48px，用 `layer-frame`，底边有一条 `line-seam`。窗口很矮时也保持 48px。
- 左边放工作空间按钮和工作空间横条，中间放搜索框，右边放正在工作的成员和铃铛。不管两侧放了什么，搜索框都在窗口中居中。
- 里面的每个控件都是 36px 的外框项，距上下各 6px。工作空间按钮与导航条的按钮对齐，和导航条一样距左边缘 8px。右侧最后一个图标（铃铛）的图标框结束在距右边缘 20px 处，和下方头部最后一个图标在同一条线上；它的按钮超出这条线 8px（[对齐](../foundations/alignment.md#the-ends-of-a-header)）。
- 在桌面应用里，把后退、前进和历史记录放在工作空间横条后面，把更新标签放在正在工作的成员前面。给窗口自己的按钮留出空间（左边是 macOS 的红绿灯按钮，右边是 Windows 的标题栏按钮），并让搜索框在整个窗口中居中，而不是在两者之间剩下的空间里居中。
- 用窗口安全区变量给窗口自己的按钮留位置，不写死数值。在页面上方画了系统按钮的外壳，会在根元素上设置：`--raft-frame-inset-start`（macOS 红绿灯那个角）、`--raft-frame-inset-end`（Windows 标题栏按钮那个角，取自 Window Controls Overlay 的尺寸）和 `--raft-frame-inset-top`（这些按钮盖住的那条带的高度）。只有真的画了这些按钮的平台才设置，全屏时不设；网页一个都不设，读出来是 0。顶栏两端按它们留白；页面里的任何东西都不画进、不放进、不弹进这些区域：主题像素画不进 `--raft-frame-inset-end`，提示碰到 `--raft-frame-inset-top` 就往反方向弹（[Tooltip](../../../packages/ui/src/components/tooltip/tooltip.md)）。
- 有顶栏时，导航条和侧栏都没有头部：导航条的第一个目的地和侧栏的第一行，都在顶栏接缝线下方 8px。

#### 头部 {#headers}

- 顶栏下面的每个头部（面板头部、侧面板头部、抽屉头部）都高 56px，这样它们底部的接缝线在整个屏幕上对齐。高度见[间距](../foundations/spacing.md#heights)。
- 没有顶栏时（较早的桌面版本、服务器的公开页面），导航条头部和侧栏头部也是 56px，导航条头部是正方形（[间距](../foundations/spacing.md#heights)）。

## 规则 {#rules}

### 从外到内的层 {#layers-from-the-outside-in}

黄色（外框），然后是奶油色（侧栏），然后是白色（内容），然后是带细线的白色卡片，然后是弹出层（`layer-popover`、接缝线描边、柔和阴影）。品牌色留在最外面，所以人工作时面对的内容是屏幕上最安静的部分。在深色模式下，每一层改为更亮一级的深色（[深色模式](../foundations/dark-mode.md)）。

### 两个区域之间只有一条线 {#one-line-between-two-regions}

- 两个区域之间只画一条线，不要两条并排：两条挨着的 1px 线看起来像一条 2px 的线。
- 线归先画的那个区域。导航条和侧栏画自己的右边缘，所以旁边的会话或动态不画左边缘。贴在会话旁边的侧面板画自己的左边缘。
- 区域之间用 `line-seam`，内容里面用 `line-hairline`（[颜色](../foundations/color.md#lines)）。

### 每一栏只有一条边 {#one-edge-per-column}

- 面板头部的第一个元素、第一张标签贴纸、消息的头像列和消息输入框的轮廓，都从同一条边距开始：桌面端 20px，手机 16px。在消息列和它的消息输入框里，手机上保持 20px。
- 每一行最后一个图标的图标框都结束在同一条边上，这样每一栏往下读时只有一条左边和一条右边。每个元素如何落在边距上，见[对齐](../foundations/alignment.md)。

### 侧栏和侧面板 {#sidebar-and-side-panel}

- 侧栏跟随导航条：它列出选中目的地里的内容。没有侧栏的目的地，把内容直接放在导航条右边。哪些目的地有侧栏，写在产品的页面上。
- 侧面板用来放和主区域一起阅读的东西：消息列、个人资料。
- 任务详情是居中的对话框，不是侧面板（[任务](./tasks.md)）。
- 一个对话所在的地方里有些东西，人们在聊天时会去查看（频道的任务、它的文件），把它们显示为对话旁边的侧边分区，而不是标签页。在频道里，消息列、Tasks 和 Files 是分区，放在整个对话面板（包括标题栏）右侧的列里；每一列是一叠分区，由人拖动来安排（[拖放](./drag-and-drop.md#where-it-will-land)）。Tasks 和 Files 用面板标题栏里的开关打开和关闭。
- 有空间时，侧边列放在布局里，而不是盖在上面：对话变窄，什么都不被盖住。侧边列和消息列的那一列一样：占满高度，左边是 `line-seam` 边，平铺，没有圆角，也没有阴影，因为只有浮起的东西才投阴影（[层级](../foundations/elevation.md)）。每个分区的头部是 56px 的面板标题栏，用这一列 20px 的边距（[间距](../foundations/spacing.md#heights)）。
- 让人们在每一列的接缝线上调整它的宽度，在两个叠放的分区之间的接缝线上调整它们的高度，并记住这些尺寸（[间距](../foundations/spacing.md#layout-widths)）。
- 宽度、行变窄时各列让出空间的顺序、消息列的那一列什么时候盖住对话、其他列什么时候浮在对话的消息上方，见[频道的侧边列](./responsive.md#the-channels-side-columns)。
- 消息列和个人资料可以同时打开：从消息列里打开个人资料，会同时显示消息列和个人资料；从会话里打开，则替换消息列。
- 个人资料或消息列什么时候放在主区域旁边、什么时候盖住主区域，见[响应式布局](./responsive.md)。
