# 响应式布局

768px 以下，Raft 是手机布局：一级页面带标签栏，其他页面都是推入的。从 768px 开始是桌面布局，有网页顶栏和导航条；空间够放两者时，侧面板放在主区域旁边。空间不够时，面板盖住主区域，而不是把主区域挤到表中的宽度以下。任务详情不随宽度变化，只是在手机上变成全屏（[任务](./tasks.md#structure)）。

## 适用范围 {#when-it-applies}

每个屏幕。各个区域本身见[页面结构](./page-structure.md)；区域的宽度见[间距](../foundations/spacing.md#layout-widths)。产品可以加上自己的条件，比如 Raft Chat 的 Search 和 Activity 两栏的宽度（[Raft Chat](../products/raft-chat/README.md#wide-and-narrow)）。

## 结构 {#structure}

| 宽度 | 布局 |
| --- | --- |
| 768px 以下 | 手机：一级页面带标签栏，其他页面都是推入的。没有网页顶栏，也没有导航条。消息列是推入的页面；个人资料像推入的页面一样盖住当前页面，带 Back |
| 768px 到 1023px | 网页顶栏、导航条、侧栏和主区域。个人资料盖住主区域 |
| 1024px 及以上 | 个人资料或任务侧面板（400px，可在 320px 到 640px 之间调整）在它打开的区域至少 720px 宽时（主区域的 360px 加面板的 360px）放在主区域旁边；否则盖住主区域 |
| 消息列，任意桌面宽度 | 窗口横向或至少 1280px 宽，并且对话所在的那一栏至少 720px 宽（对话的 360px 加消息列最小的 360px）时，放在对话旁边；否则盖住对话。放在旁边时，消息列 400px（可在 360px 到 720px 之间调整），对话至少保留 360px |
| 对话旁边的侧边卡片 | 卡片放在对话的面板里、面板标题栏下面，在消息列表和消息输入框的右侧。消息列不属于它们：消息列保留自己在整个面板（包括标题栏）右侧的那一栏（上一行），打开它只会让面板变窄；卡片留在原处。面板放得下消息列表（至少 360px，主区域的最小宽度，和消息列旁边一样）和卡片（这一栏 12px 留白以内至少 280px：面板 652px）时，卡片占一栏，消息列表变窄。放不下时，卡片作为一张带 `float` 阴影的卡片浮在消息列表的右侧，离面板各边 12px，在消息输入框上方，这样消息保持宽度。两张都打开时，只要消息旁边放得下两张 160px 的卡片，它们就上下叠放；浮动时，或者面板矮得放不下两张时，一次显示一张，上面是一行 Tasks / Files [标签页](../../packages/ui/src/components/tabs/tabs.md)（内容不同，所以用标签页，不用分段控件），最后打开或选中的那张排在前面。标签页从卡片 16px 的边距开始，也就是卡片标题和各行开始的地方。768px 以下，以及面板窄得放不下一张 280px 的浮动卡片加 240px 可读的消息时（小于 520px，比如 1024px 的窗口打开了消息列），卡片盖住面板标题栏下面的部分，包括消息输入框，并带 Back |
| 高度不到 600px 的桌面窗口 | 标题栏从 56px 收缩到 48px；导航条随之从 57px 宽收缩到 49px 宽；导航条的项从 40px 收缩到 36px。网页顶栏保持 48px |

移动 App 同样按窗口宽度切换，但用它们自己的断点：从 840dp 起，在开启 App 的桌面模式时，显示导航条和两栏而不是标签栏，横屏和平板都一样；从 1200dp 起，消息列放在对话旁边。导航条用 [AppRail](../../packages/ui/src/components/app-rail/app-rail.md) 绘制，保留手机上的目的地和顺序。保留每个平台各自的断点（网页 768px，App 840dp），不要强行统一：断点是布局的搭建方式，而导航的结构在哪里都一样，见[导航](./navigation.md#principles)。

```example
app-shell/compositions/responsive
```

## 规则 {#rules}

### 按所在区域的宽度切换 {#switch-on-the-regions-width}

布局按它所在那一块的宽度切换，而不是窗口的宽度。同一个组件可能放在 1440px 窗口里一个 320px 的面板中，也可能铺满 390px 的手机：窗口宽度说明不了它有多少地方。资料面板、对话旁的 thread、弹窗、Activity 列表都比窗口窄；去问窗口的布局，仍会按一块它并没有的屏幕来排：360px 面板里出现两栏的列表，本该竖排的步骤行却折了行。

- **面板、栏、卡片里的内容，用那一块上的容器查询**：在那一块上加 `@container`，里面的东西用 `@sm:`、`@max-[…]:` 之类。自己切换布局的组件把自己设为容器，放到哪里都对；这样它会占满所在行的宽度，因为容器的宽度不能由里面的内容决定。所以要给它一个宽度确定的父元素：块级元素、被拉伸的 flex 或 grid 子项，或设了宽度的元素。放在按内容收缩的父元素里（`inline-block`、`w-fit` 或 `fit-content`、没设宽度的绝对定位框或浮层、`flex-basis: auto` 又没设宽度的 flex 子项），它会缩成零宽，文字一行一个词。把自己设为容器的组件会在各自的页面上写明这一点。
- **只有大小由窗口决定的东西才看窗口**：页面外框和它的断点（上表）、弹窗、底部弹层、toast、通知中心，以及面板头部在手机上的边距（手机上面板就是整页）。
- **鼠标还是触屏用 `pointer` 和 `hover` 判断，从不用宽度**（[触屏](#touch-screens)）：平板在 1024px 也是触屏，窄的桌面窗口照样有鼠标。
- **用脚本量出来的尺寸要一直量。** 观察当前挂着的那个元素（用 callback ref，不要在 effect 里只读一次 ref），它变大小、内容变了都重新量（在它上面挂 `ResizeObserver`；内容变化用 `MutationObserver` 或 layout effect：行内元素里的文字变了，`ResizeObserver` 不会报告）。只量一次的结果，在内容晚到、字体加载完或元素被换掉时就错了。
- **能不切换就不切换。** 会换行的一行、用 `auto-fill` 的网格、写成 `min(360px, 100%)` 而不是 `100vw` 减去对外框的估计的宽度：这些放在任何区域都合适，不用问它多宽。

2026-10 的梳理里，在窄区域里坏掉的布局有三种原因：按窗口宽度切换、只量一次、一行东西没有让位的办法。本节讲前两种，下一节讲第三种。

### 一行放不下时 {#when-a-row-runs-out-of-room}

每一行都要有让位的办法。工具栏、标题栏、筛选行或列表行必须在它所在区域能取到的最窄宽度下（Activity 的结果列表最窄到 320px）、用最长的译文和它可能装下的最长的值（邮箱地址中间没有可以断开的空格）时也放得下。放不下时，各部分按固定顺序让位，让人仍能看到每个控件：

1. 次要的文字按钮只显示图标，标签保留为无障碍名称和工具提示。Mark all read 变成 `check-check` 图标按钮。
2. 然后才轮到主控件只显示图标：分段控件的各段、标签页的标签。分段控件在宽度低于 `iconsOnlyBelow` 设定的行宽时自己这样做：每段变成一个 32px 的方块，只有图标，标签保留为无障碍名称和工具提示（[SegmentedControl](../../packages/ui/src/components/segmented-control/segmented-control.md#behavior)）。
3. 一行控件仍然放不下时，折到第二行，控件保持完整；不能只显示图标的分段控件在自己的轨道里横向滚动，而不是溢出到旁边的控件上（[SegmentedControl](../../packages/ui/src/components/segmented-control/segmented-control.md#behavior)）。
4. 文字最后才截断，而且只截断名字或值（频道、人、邮箱、时间），从不截断控件的标签。

- 各部分不能重叠，控件也不能缩到比自己的内容还小：给控件包上 `min-w-0`，它的外框会缩小，内容却溢出到旁边的控件上。
- 每个能让位的部分都要给它让位的手段：可能被截断的文字加 `min-w-0` 和 `truncate`，一排控件加 `flex-wrap`，可能变窄的行里的分段控件设 `iconsOnlyBelow`。既不能缩、不能折行、也不能截断的那个部分，就是溢出的那个。
- 用这一行上的容器查询（`@container`、`@max-[…]:`）决定何时切换，而不是窗口宽度（[按所在区域的宽度切换](#switch-on-the-regions-width)）。
- 不要为了放下一行而缩小文字或控件高度：小到读不清的标签、小到点不中的目标，比带工具提示的图标更糟。

### 触屏 {#touch-screens}

触屏没有悬停，所以只在悬停时出现的东西在触屏上够不到。按输入方式判断，而不是按宽度：用 `pointer: coarse` 媒体查询，因为横放的平板是触屏，而窄的桌面窗口仍然用鼠标。

- 用鼠标时，一行的操作只在悬停时出现，Activity 行上的 Mark as Done 也一样：在这一行被悬停、拥有键盘焦点或从它打开了菜单时显示，静止时隐藏。每一行都显示按钮的列表读起来像一堵按钮墙，会把视线从内容上拉走；而且鼠标要点的本来就是这一行。隐藏的操作仍在 Tab 顺序里。
- 在触屏上，如果悬停操作是这一行的主操作（比如 Activity 行上的 Mark as Done），静止时也显示：在行尾放一个 44px 的目标，带图标。行的其余部分给它让出位置，而不是垫在它下面（[InboxItem](../../packages/ui/src/components/inbox-item/inbox-item.md#behavior)）。
- 每个悬停操作也放进这一行的长按菜单里，就是桌面端右键打开的那个菜单，这样每个操作在每种设备上都只在一个地方（[对话](./conversation.md)）。
- 滑动可以作为这一行主操作的快捷方式（左滑露出 Mark as Done，松手执行，并弹出带 Undo 的轻提示），但不能是唯一的入口（[无障碍](../foundations/accessibility.md)）。
- 在触屏上，次要的悬停操作不放在行里；它们放在菜单里，让列表保持安静。

### 手机 {#phone}

- 按 390px 宽设计，并保证在 320px 下所有东西都放得下，这是仍在使用的最窄的手机。
- 长名字截断。长值在表单输入框里怎么处理、哪些内容改为换行，见[表单](./forms.md#long-values-in-fields)。
- 按钮可以换到新的一行。不要缩小按钮文字：小到读不清的标签比高一点的按钮更糟。
- 分段控件最多 4 段。放不下时只显示图标，标签保留为无障碍名称（`iconsOnlyBelow`）。
- 标签页放不下时横向滚动（[Tabs](../../packages/ui/src/components/tabs/tabs.md)）。
- 触屏上的消息输入框和消息操作，见[对话](./conversation.md#the-composer)。
