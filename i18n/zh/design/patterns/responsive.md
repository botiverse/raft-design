# 响应式布局

768px 以下，Raft 是手机布局：一级页面带标签栏，其他页面都是推入的。从 768px 开始是桌面布局，有网页顶栏和导航条；空间够放两者时，侧面板放在主区域旁边。空间不够时，面板盖住主区域，而不是把主区域挤到表中的宽度以下；对话所在的这一行例外，它的各列会变窄、裁切、变成标签页，消息列则叠到对话上（[频道的侧边列](#the-channels-side-columns)）。任务详情不随宽度变化，只是在手机上变成全屏（[任务](./tasks.md#structure)）。

## 适用范围 {#when-it-applies}

每个屏幕。各个区域本身见[页面结构](./page-structure.md)；区域的宽度见[间距](../foundations/spacing.md#layout-widths)。产品可以加上自己的条件，比如 Raft Chat 的搜索和动态两栏的宽度（[Raft Chat](../products/raft-chat/README.md#wide-and-narrow)）。

## 结构 {#structure}

| 宽度 | 布局 |
| --- | --- |
| 768px 以下 | 手机：一级页面带标签栏，其他页面都是推入的。没有网页顶栏，也没有导航条。消息列是推入的页面；个人资料像推入的页面一样盖住当前页面，带 Back |
| 768px 到 1023px | 网页顶栏、导航条、侧栏和主区域。个人资料盖住主区域；在对话所在的这一行里例外，个人资料是这一行的一列（[频道的侧边列](#the-channels-side-columns)） |
| 1024px 及以上 | 个人资料或任务侧面板（400px，可调整，最窄 160px，内容比 320px 窄时被裁切，最宽到主区域缩到它的 360px 为止）在它打开的区域至少 720px 宽时（主区域的 360px 加面板的 360px）放在主区域旁边；否则盖住主区域。在对话所在的这一行里，个人资料是这一行的一列，从不盖住对话 |
| 消息列，任意桌面宽度 | 只要它和对话合起来至少有 720px，并且没有别的列不得不裁切，它就在对话旁边单独成一列；否则它叠进对话这一列，盖在对话上，带 Back（[频道的侧边列](#the-channels-side-columns)）。在竖着拿、宽度不到 1280px 的触屏平板（`pointer: coarse`）上，比如 iPad mini，不管空间多少，它都叠在对话上 |
| 对话所在这一行的各列 | 先是对话，然后是它右边各列里的消息列、Tasks、Files、Artifact 和个人资料，每一列是人自己排列的一摞分区（[拖放](./drag-and-drop.md#where-it-will-land)）。每一列在这一行里占满高度，宽度由这一行按它保存的宽度分给它，最窄 160px，比内容最小宽度窄时内容被裁切；没有什么浮在这一行上面。到了 160px 还放不下，最右边的列变成它左边那一列头部里的标签页（[频道的侧边列](#the-channels-side-columns)） |
| 高度不到 600px 的桌面窗口 | 标题栏从 56px 收缩到 48px；导航条随之从 57px 宽收缩到 49px 宽；导航条的项从 40px 收缩到 36px。网页顶栏保持 48px |

移动 App 同样按窗口宽度切换，但用它们自己的断点：从 840dp 起，在开启 App 的桌面模式时，显示导航条和两栏而不是标签栏，横屏和平板都一样；从 1200dp 起，消息列放在对话旁边。导航条用 [AppRail](../../packages/ui/src/components/app-rail/app-rail.md) 绘制，保留手机上的目的地和顺序，服务器标签除外：在那里，服务器是导航条头部的工作空间图块，是切换服务器的唯一入口，和网页一样。手机上从服务器标签进入的那些服务器页面，在这里各有自己的入口（[导航](./navigation.md#the-server-in-the-apps-desktop-mode)；Raft Chat 的入口见 [Raft Chat](../products/raft-chat/README.md#the-server-tab)）。保留每个平台各自的断点（网页 768px，App 840dp），不要强行统一：断点是布局的搭建方式，而导航的结构在哪里都一样，见[导航](./navigation.md#principles)。

折叠屏手机的外屏保持手机布局，系统的竖列在它的一侧；它的内屏是桌面模式（[页面结构](./page-structure.md#foldable-phones)）。

app-shell/compositions/responsive

### 频道的侧边列 {#the-channels-side-columns}

对话所在的这一行是一排列：最左边是对话，然后是它右边的各列。消息列、Tasks、Files、Artifact 和个人资料是一个个分区，由人放进这些列里，每一列是叠起来的若干分区；除了消息列自己的一列，侧边列最多四列：这是侧边布局从各列可以排列起（task #165）就有的上限，原型沿用了它。在有人移动它们之前，消息列自己占一列（400px），Tasks 叠在 Files 上面，在它右边（360px），再往右是 Artifact（480px），然后是个人资料（400px）；对话占它们留下的空间，在它旁边的接缝第一次被拖动之前至少 400px。每一列在这一行里占满高度，左边是一条 `line-seam` 边线，平的，没有阴影。没有什么浮在这一行上面：每一列，包括对话那一列，都站在这一行里，只有消息列会叠到对话上，作为对话的一层。叠放的分区分享这一列的高度，每个至少 160px；在矮得放不下两个的列里，一次显示一个，上面是一行[标签页](../../packages/ui/src/components/tabs/tabs.md)。这些规则由 stdrc 确定（2026-11-03 和 2026-11-04，#proj-raft-ui:#189）。

- **每条接缝都在相邻的两列之间交换宽度。** 拖动接缝，一边的列变宽多少，就从另一边的列拿走多少。那一列缩到 160px 后，拖动接着从同一侧更外面的下一列拿，一直到这一行的尽头（连锁）。每条接缝都这样，对话旁边的也一样。松开时显示的宽度就是保存的宽度：不会弹回去。有一列展开着的时候拖动接缝，先把这一行按当前显示的样子保存下来，并结束展开。
- **列最窄 160px；内容保留它的最小宽度。** 内容的最小宽度：对话和消息列 360px，Tasks 和 Files 280px，Artifact 480px，个人资料 320px；一摞分区取其中最宽的。列比这窄时，内容保持最小宽度，贴着列的起始边，多出的部分裁掉，不出滚动条，内容的末端按 `fade-edge` 渐隐，这样截断处读起来是「内容还在继续」（[边缘渐隐](../foundations/spacing.md#edges-fade)）。头部从不被裁切：它适应这一列（[Panel](../../packages/ui/src/components/panel/panel.md#rules)）。
- **这一行从不改写保存的宽度。** 一列保存的宽度就是人留给它的宽度：只在人松开接缝或移动分区时改变，另外在消息列回到单独一列时，对话和消息列的宽度会改变（见下文）。窗口、侧栏、消息列叠起来、打开或关闭一列、Expand，都只改变这一行显示的样子，所以空间回来时，这一行回到人留下的样子。空间有富余时，每一列按保存的宽度成比例变宽，所以这一行总是填满的。
- **侧栏的开关等于窗口变化。** 侧栏不是这一行的一列：它保持自己的宽度，所以消息列打开或叠起来时它不会跳动。这一行的空间是窗口减去导航条和侧栏，所以收起或展开侧栏，就是给这一行多出或拿走侧栏的宽度，和窗口宽了或窄了这么多一样。这一行按下面的顺序重新排布，保存的宽度不变，展开着的那一列保持展开。

这一行的空间比各列保存的宽度少时，按这个顺序让位；变宽时按相反的顺序走回去：

1. 每一列按比例让出内容最小宽度以上的部分。这时不会有新的裁切：只有保存的宽度本来就比内容最小宽度窄的一列，从一开始就被裁切。
2. 对话和消息列合起来不到 720px，或者让它们并排会让别的列裁切时，消息列叠到对话上：叠起来总在裁切之前。在宽的一行里，人把消息列拖到比 360px 还窄时，它仍单独成一列，被裁切。
3. 叠着消息列的对话那一列让位，直到 360px。
4. 所有列按比例一起缩，开始裁切，直到 160px。
5. 这一行给不了每一列 160px 时，最右边的列变成它左边那一列头部里的标签页，代替那个头部的标题，然后是下一列，依此类推。选中的标签在那个位置显示它的列；选中哪一个不会被保存。标签页占满头部的整个标题空间，放不下时在标签行的边缘渐隐下横向滚动；一个标签从不和整行标签一样宽，所以下一个总露出一截（[Tabs](../../packages/ui/src/components/tabs/tabs.md)）。

消息列是对话的一层，所以它先叠起来，其他东西才需要让位：

- **叠起来时，消息列在对话那一列里，盖在聊天上面**，两者共用这一列的宽度。它的头部以 Back 开头，按了关闭消息列，露出下面的聊天；头部没有 ×（[导航](./navigation.md#closing)）。对话留在下面，够不着（不能聚焦，不接指针，不被读出），保留滚动位置和草稿，回来时原样不变。和分区叠在同一列里的消息列叠起来时离开那一列，那些分区留在原处。
- **空间一够，它就重新单独成一列**，不需要先多出一段余量。回来时，两者分配它们的宽度，让谁都不从 360px 以下开始。
- 在叠起来的那一列上拖动接缝，改变的是两者合起来的宽度，按对话和消息列保存的宽度分配。
- 在竖着拿、宽度不到 1280px 的触屏平板（`pointer: coarse`）上，不管空间多少，消息列都叠在对话上。精确指针在任何宽度下都按上面的顺序。

每一列的头部都有 Expand，紧挨在 Close 前面，对话的头部也有（[Panel](../../packages/ui/src/components/panel/panel.md#rules)）。展开后，这一列占满整行，其他每一列保持 160px 并裁切，所以这一行其余的部分仍以窄条的形式留在视野里。再按一次 Expand，或按 Esc，这一行回到原来的样子，一个像素不差。同一时间只展开一列；消息列保持展开那一刻的状态，叠着或在对话旁边。一列里上下叠着几块时，展开的那一块同时占满这一列的高度，其他几块只显示各自的头部，顺序不变，展开期间没有折叠箭头，也没有可拖的分隔线；恢复后每一块的高度和折叠状态都回到原来的样子（stdrc，2026-11-04，#proj-raft-ui:aedc53e1）。其他几块各自保留 Expand：按一下就把展开切到那一块，这一列仍然占满整行。只显示头部的一块贴在这一列底边、上面有一块显示着内容时，它不在底边画线；这一列里所有块都只显示头部时，每一块都保留自己的线（stdrc，2026-11-04）。有一列展开着时又打开一列，先把这一行恢复原样，新的一列再按上面的顺序就位。Esc 先恢复这一行，才轮到这一列里的东西（消息列自己的 Esc），但打开着的菜单或对话框先拿到它。

消息列、Tasks、Files、Artifact 和个人资料用抓手移动（[拖放](./drag-and-drop.md#where-it-will-land)），或者用头部 ⋯ 里的 Move left 和 Move right（[拖放](./drag-and-drop.md#keyboard)）。对话不能移动：放到它上面的分区，在消息列后面成为新的一列。单独一列里的分区移出来，保留那一列的宽度；从一摞里移出来的分区用它的默认宽度；它加入的那一列保持自己的宽度。新的一列总能站在这一行里，必要时被裁切或成为标签页，所以不会因为空间不够而拒绝新的一列。有一列展开时什么都不能移动；叠在对话上的消息列也不能移动：它是对话的一层，不是一列。

在手机上，消息列是推入的页面，分区盖住对话标题栏下面的部分，在标签页下一次显示一个，并带 Back。这些切换是瞬时的，没有动画（[动效](../foundations/motion.md#usage)）。

## 规则 {#rules}

### 按所在区域的宽度切换 {#switch-on-the-regions-width}

布局按它所在那一块的宽度切换，而不是窗口的宽度。同一个组件可能放在 1440px 窗口里一个 320px 的面板中，也可能铺满 390px 的手机：窗口宽度说明不了它有多少地方。资料面板、对话旁的消息列、弹窗、动态列表都比窗口窄；去问窗口的布局，仍会按一块它并没有的屏幕来排：360px 面板里出现两栏的列表，本该竖排的步骤行却折了行。

- **面板、栏、卡片里的内容，用那一块上的容器查询**：在那一块上加 `@container`，里面的东西用 `@sm:`、`@max-[…]:` 之类。自己切换布局的组件把自己设为容器，放到哪里都对；这样它会占满所在行的宽度，因为容器的宽度不能由里面的内容决定。所以要给它一个宽度确定的父元素：块级元素、被拉伸的 flex 或 grid 子项，或设了宽度的元素。放在按内容收缩的父元素里（`inline-block`、`w-fit` 或 `fit-content`、没设宽度的绝对定位框或浮层、`flex-basis: auto` 又没设宽度的 flex 子项），它会缩成零宽，文字一行一个词。把自己设为容器的组件会在各自的页面上写明这一点。
- **只有大小由窗口决定的东西才看窗口**：页面外框和它的断点（上表）、弹窗、底部弹层、toast、通知中心，以及面板头部在手机上的边距（手机上面板就是整页）。
- **鼠标还是触屏用 `pointer` 和 `hover` 判断，从不用宽度**（[触屏](#touch-screens)）：平板在 1024px 也是触屏，窄的桌面窗口照样有鼠标。
- **用脚本量出来的尺寸要一直量。** 观察当前挂着的那个元素（用 callback ref，不要在 effect 里只读一次 ref），它变大小、内容变了都重新量（在它上面挂 `ResizeObserver`；内容变化用 `MutationObserver` 或 layout effect：行内元素里的文字变了，`ResizeObserver` 不会报告）。只量一次的结果，在内容晚到、字体加载完或元素被换掉时就错了。
- **能不切换就不切换。** 会换行的一行、用 `auto-fill` 的网格、写成 `min(360px, 100%)` 而不是 `100vw` 减去对外框的估计的宽度：这些放在任何区域都合适，不用问它多宽。

2026-10 的梳理里，在窄区域里坏掉的布局有三种原因：按窗口宽度切换、只量一次、一行东西没有让位的办法。本节讲前两种，下一节讲第三种。

### 一行放不下时 {#when-a-row-runs-out-of-room}

每一行都要有让位的办法。工具栏、标题栏、筛选行或列表行必须在它所在区域能取到的最窄宽度下（动态的结果列表最窄到 320px）、用最长的译文和它可能装下的最长的值（邮箱地址中间没有可以断开的空格）时也放得下。放不下时，各部分按固定顺序让位，让人仍能看到每个控件：

1. 次要的文字按钮只显示图标，标签保留为无障碍名称和工具提示。Mark all read 变成 `check-check` 图标按钮。
2. 然后才轮到主控件只显示图标：分段控件的各段、标签页的标签。分段控件设了 `iconsOnlyBelow="auto"` 时自己这样做，正好在它的标签放不进给它的空间时：每段变成一个 32px 的方块，只有图标，标签保留为无障碍名称和工具提示（[SegmentedControl](../../packages/ui/src/components/segmented-control/segmented-control.md#behavior)）。
3. 一行控件仍然放不下时，折到第二行，控件保持完整；不能只显示图标的分段控件在自己的轨道里横向滚动，而不是溢出到旁边的控件上（[SegmentedControl](../../packages/ui/src/components/segmented-control/segmented-control.md#behavior)）。
4. 文字最后才截断，而且只截断名字或值（频道、人、邮箱、时间），从不截断控件的标签。

- 各部分不能重叠，控件也不能缩到比自己的内容还小：给控件包上 `min-w-0`，它的外框会缩小，内容却溢出到旁边的控件上。
- 每个能让位的部分都要给它让位的手段：可能被截断的文字加 `min-w-0` 和 `truncate`，一排控件加 `flex-wrap`，可能变窄的行里的分段控件设 `iconsOnlyBelow="auto"`。既不能缩、不能折行、也不能截断的那个部分，就是溢出的那个。
- 用这一行上的容器查询（`@container`、`@max-[…]:`）决定何时切换，而不是窗口宽度（[按所在区域的宽度切换](#switch-on-the-regions-width)）。如果要切换的是某个部分的内容放不放得下，就去量内容，而不是猜一个宽度，像 `iconsOnlyBelow="auto"` 那样：按一种语言或一个数量挑出来的宽度，换一种就不对了。
- 不要为了放下一行而缩小文字或控件高度：小到读不清的标签、小到点不中的目标，比带工具提示的图标更糟。

### 第一帧就是稳定下来的样子 {#the-first-frame-is-the-settled-one}

第一帧就按它之后会保持的样子画。用「还不知道」的默认值画出一帧、过一会儿再修正，就是一次闪动：一行变宽又缩回去，一个面板以一个宽度打开又跳到另一个宽度，一张卡片突然出现、把页面往下推。在那一刻，人看到的是一个本不该出现的布局，控件还在鼠标指针下面移动。

- **在第一次绘制之前读出决定布局的东西。** 记住的宽度、收起的区块和视图模式从存储里读进初始状态；视口、指针类型和平台也一样。不要在挂载后的 effect 里读它们：effect 在浏览器绘制之后才运行。
- **在 layout effect 里测量，并在那里做决定**，而不是在下一个动画帧里：在 layout effect 里设置的状态，会在浏览器绘制之前重新渲染。只有之后的测量（比如尺寸变化时）才等一帧。
- **数据重新加载时，保持一个部分的有无和大小。** 列表因为换了筛选而重新加载时，计数，以及只在有计数时才显示的控件，都保持上一次的值，直到新的结果到来。不要把它们降成空的默认值再恢复。在那一刻消失的控件会把它的空间让给旁边的部分，它们就会重新排一遍：设了 `iconsOnlyBelow="auto"` 的分段控件会先显示标签，然后又变回图标。
- **占位占据它所代表的东西的大小和位置。** 代码懒加载的面板，它的 fallback 是这个面板自己的框，用记住的宽度，而不是这一行剩下的空间。骨架屏和它的内容一样大（[反馈](./feedback.md#empty-loading-and-failed)）。
- **真正的结果到来时，只变一次：** 从旧值直接变成新值，从不经过一个空值。

### 触屏 {#touch-screens}

触屏没有悬停，所以只在悬停时出现的东西在触屏上够不到。按输入方式判断，而不是按宽度：用 `pointer: coarse` 媒体查询，因为横放的平板是触屏，而窄的桌面窗口仍然用鼠标。

- 用鼠标时，一行的操作只在悬停时出现：在这一行被悬停、拥有键盘焦点或从它打开了菜单时显示，静止时隐藏。每一行都显示按钮的列表读起来像一堵按钮墙，会把视线从内容上拉走；而且鼠标要点的本来就是这一行。隐藏的操作仍在 Tab 顺序里。
- 在触屏上，如果悬停操作是这一行的主操作，静止时也显示：在行尾放一个 44px 的目标，带图标。行的其余部分给它让出位置，而不是垫在它下面（[InboxItem](../../packages/ui/src/components/inbox-item/inbox-item.md#behavior)）。
- 在手机上，Raft Chat 有一个例外，是动态行上的 Mark as Done（[Raft Chat](../products/raft-chat/README.md#activity-on-a-phone)）。
- 每个悬停操作也放进这一行的长按菜单里，就是桌面端右键打开的那个菜单，这样每个操作在每种设备上都只在一个地方（[对话](./conversation.md)）。
- 滑动可以作为这一行各个操作的快捷方式（左滑把它们作为按钮露出来，并弹出带 Undo 的轻提示），但不能是唯一的入口：长按菜单里有同样的操作（[无障碍](../foundations/accessibility.md)）。消息没有滑动手势：在对话里向左拖是用来露出时间的（见下）。
- 只有手指明显横向移动时，才开始滑动一行：横向距离是上下距离的两倍以上，并且超过平台的触摸容差（touch slop）。拖动开始后变成竖向的，就回到滚动列表。否则人在滚动列表时会不小心滑动其中的行。
- 在超过平台的触摸容差之后再做这个判断；网页没有触摸容差，用 10px，所以「两倍」这条规则在手指移动了 20px 时判断。从屏幕左右边缘 24px 以内开始的滑动留给浏览器和系统，它们的返回和切换应用手势从那里开始。
- 左滑在行尾露出这一行的操作按钮，再点其中一个，和 iOS Mail 一样（stdrc，2026-10-23）。松手时超过按钮宽度的一半，或者超过容差后向左快速一划，这一行就停在打开的状态；不到一半，或者向回一划，它就弹回去。只有距离会执行 Done，快速一划从不会，所以快速滑动不会不小心完成一行。拉过行宽的 60% 后松手，立即执行第一个操作 Done：最常用的操作仍然只要一个手势。一次只打开一行：点别的任何地方、滚动列表、把这一行滑回去或打开另一行，都会关上它。有一行打开时，在列表里点一下只会关上它，和 iOS Mail 一样；在列表外点一下（轻提示的 Undo、标签栏），会关上它，并执行所点的东西本来的操作。
- 按钮画在行尾，主操作在最外侧：先是 Done，然后向内是这一行的其他操作（Unfollow、Mute），每个 72px 宽、和行一样高，18px 的图标在上，下面是一个 `text-caption`、字重 600 的词：彩色填充上的一个短词必须一眼就能读出来。Done 是实色 `success` 配墨色；其他按钮是 `fill-muted` 配 `foreground`，这样只有一个操作突出，其余保持安静。超过 60% 的位置后，Done 按钮变宽，盖过其他按钮，占满整个露出的宽度，在 Android 上手机轻震一次（10ms 振动，浏览器支持时）；退回到这个位置以内，按钮恢复原样。下拉刷新用同样的方式显示就绪和解除，包括轻震（[导航](./navigation.md#refreshing)）：手指松开之前必须知道结果。按钮上的词是操作最短的名字（"Done"、"Unfollow"、"Mute"），因为按钮很小；菜单项保留完整的名字（"Mark as Done"）。图标就是这个操作在这一行菜单里的图标（Done 是 `check`，Unfollow 是 `UnfollowThreadIcon`（[Icons](../../packages/ui/src/components/icons/icons.md#action-icons)），Mute 是 `bell-off`），这样两个按钮永远不会看起来像同一个操作，菜单也就教会了人怎么滑。
- 操作把这一行移出列表时（Done、Unfollow），立即移出，并在轻提示里给一个 Undo，这样的轻提示保留 8 秒（[Toast](../../packages/ui/src/components/toast/toast.md)）。有确切反操作的操作立即执行，Undo 执行它的反操作（Mute 和 Unmute），和这一行的菜单一样。没有反操作的操作等着轻提示：轻提示关闭时、另一行的操作被执行时（那一行的轻提示取代这一条），或者离开列表、页面被隐藏时，才执行。Undo 把这一行原样放回原来的位置。动态里的 Done、Unfollow 和 Mute 怎么表现，见 [Raft Chat](../products/raft-chat/README.md#activity-on-a-phone)。
- 处理这一行的操作（上面那些）都用左滑，全放在一侧：三个操作分到两个方向上不好分（stdrc，2026-10-23）。这类操作只有 Done 的行，就只显示这一个按钮。右滑留给唯一一个只改变这一行已读与否的操作，和 iOS Mail 一样：未读的行上是 Mark as read，已读的行上是 Mark as unread（artin 和 stdrc，2026-10-24）。它是行首的一个按钮，用菜单项的图标（`message-square-check`、`message-square-dot`），下面是它最短的词（"Read"、"Unread"），用 `fill-muted` 配 `foreground`，距离也和左滑一样：超过它宽度的一半就停在打开状态，拉过 60% 就执行。这一行留在原处，所以没有轻提示，也没有 Undo：再滑一次就切换回去。屏幕左边缘的 24px 仍然留给系统的返回手势。超过 60% 的位置后，它的图标和词随这一行的边缘移动，和 iOS Mail 一样，让手指知道松开就会执行；Android 上和 Done 一样轻震一次。滑动没法在屏幕上改变已读状态的行没有右滑：在这样的行上滑动，要么什么都显示不出来，要么没法滑回去。它的菜单保留原有的内容。动态里哪些行是这样，以及筛选怎么留住刚标为已读的行，见 [Raft Chat](../products/raft-chat/README.md#activity-on-a-phone)。
- 在可以滑动的行上，横向拖动在两个方向上都归这一行，所以列表的标签页或筛选在那里不会也靠横向滑动切换：改为点它们（artin，2026-10-26）。一次拖动对应两种手势，每次滑动就都成了猜测。
- 在对话里，向左的横向拖动归列表：它露出每条消息的时间（[对话](./conversation.md#dates-and-grouping)；artin，2026-11-04，#triage:530f8c36）。判断方式和滑动一行一样：横向距离是上下距离的两倍以上，在手指移动了 20px 时判断，从屏幕左右边缘 24px 以内开始的拖动一律不接手。在那里向右拖什么也不做。这些行从手指按下的位置起跟着手指走，所以不会落后于手指，也不会跳，松手后弹回。开启减弱动态效果时什么都不滑动：改为每条合并消息的时间在它左侧空着的位置淡入，不在文字上画任何东西（在行尾淡入的时间会压在标题栏的时间和正文上）。具体的距离和时长见[动效](../foundations/motion.md#usage)。
- 在标签页靠横向滑动切换的对话里关掉时间展开（App 里仍有 Chat、Tasks、Files 标签页的对话，即没有 task v2 对话的服务器），免得两种拖动互相抢。其他地方都开着：task v2 对话、消息列、任务讨论、助手面板。网页上没有哪个对话的标签页靠滑动切换（都是点按切换），所以每个对话都开着。
- 这个拖动留给它开始的地方：代码块、宽表格、行间公式、Mermaid 图、输入框、滑块、媒体，以及其他能横向滚动而且确实有内容可滚的东西。从宽表格里开始的拖动，即使表格已经滚到头，也仍然归表格，所以一次拖动不会从滚动表格变成滑动列表。有弹出层打开时，或者长按已经打开了消息菜单之后，拖动都不会开始展开时间。
- 被对话接手的拖动不算点按：它不会打开消息列，不算双击的一次，也不会打开菜单（[触屏上的点按](../foundations/states.md#taps-on-a-touch-screen)）。
- 在对话上保留双指缩放：消息行保留 `touch-action: manipulation`（这样双击不会缩放），拖动的监听也不阻塞滚动，而不是改用 `touch-action: pan-y`：iOS Safari 没有 `pan-y pinch-zoom`，`pan-y` 会连双指缩放一起关掉。代价是斜着拖时列表也可能滚动一点。
- 在触屏上，次要的悬停操作不放在行里；它们放在菜单里，让列表保持安静。

### 手机 {#phone}

- 按 390px 宽设计，并保证在 320px 下所有东西都放得下，这是仍在使用的最窄的手机。
- 长名字截断。长值在表单输入框里怎么处理、哪些内容改为换行，见[表单](./forms.md#long-values-in-fields)。
- 按钮可以换到新的一行。不要缩小按钮文字：小到读不清的标签比高一点的按钮更糟。
- 分段控件最多 4 段。放不下时只显示图标，标签保留为无障碍名称（`iconsOnlyBelow="auto"`）。
- 标签页放不下时横向滚动（[Tabs](../../packages/ui/src/components/tabs/tabs.md)）。
- 触屏上的消息输入框和消息操作，见[对话](./conversation.md#the-composer)。
