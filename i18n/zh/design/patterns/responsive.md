# 响应式布局

768px 以下，Raft 是手机布局：一级页面带标签栏，其他页面都是推入的。从 768px 开始是桌面布局，有网页顶栏和导航条；空间够放两者时，侧面板放在主区域旁边。空间不够时，面板盖住主区域，而不是把主区域挤到表中的宽度以下。任务详情不随宽度变化，只是在手机上变成全屏（[任务](./tasks.md#structure)）。

## 适用范围 {#when-it-applies}

每个屏幕。各个区域本身见[页面结构](./page-structure.md)；区域的宽度见[间距](../foundations/spacing.md#layout-widths)。产品可以加上自己的条件，比如 Raft Chat 的 Search 和 Activity 两栏的宽度（[Raft Chat](../products/raft-chat/README.md#wide-and-narrow)）。

## 结构 {#structure}

| 宽度 | 布局 |
| --- | --- |
| 768px 以下 | 手机：一级页面带标签栏，其他页面都是推入的。没有网页顶栏，也没有导航条。消息列是推入的页面；个人资料像推入的页面一样盖住当前页面，带 Back |
| 768px 到 1023px | 网页顶栏、导航条、侧栏和主区域。个人资料盖住主区域 |
| 1024px 及以上 | 个人资料或任务侧面板（400px，可调整，最窄 320px，最宽到主区域缩到它的 360px 为止）在它打开的区域至少 720px 宽时（主区域的 360px 加面板的 360px）放在主区域旁边；否则盖住主区域 |
| 消息列，任意桌面宽度 | 窗口横向或至少 1280px 宽，并且对话所在的那一栏至少 720px 宽（对话的 360px 加消息列最小的 360px）时，放在对话旁边；否则盖住对话。放在旁边时，消息列 400px（可调整，最窄 360px，最宽到对话缩到它的 360px 为止），对话至少保留 360px。在有侧边列的频道里，消息列所在的列是其中之一；这一行放不下所有列的最小宽度时，它连同叠在里面的分区一起盖住对话（[频道的侧边列](#the-channels-side-columns)） |
| 对话旁边的侧边列 | Thread、Tasks 和 Files 是分区，放在整个对话面板（包括标题栏）右侧的列里，每一列是人自己排列的一摞分区（[拖放](./drag-and-drop.md#where-it-will-land)）。每一列在这一行里占满高度，用自己的宽度，最窄到它的最小宽度，同时对话保留 360px。再窄下去，打开了消息列时，Thread 所在的列盖住对话；没有打开消息列时，其他列浮在消息上面（[频道的侧边列](#the-channels-side-columns)） |
| 高度不到 600px 的桌面窗口 | 标题栏从 56px 收缩到 48px；导航条随之从 57px 宽收缩到 49px 宽；导航条的项从 40px 收缩到 36px。网页顶栏保持 48px |

移动 App 同样按窗口宽度切换，但用它们自己的断点：从 840dp 起，在开启 App 的桌面模式时，显示导航条和两栏而不是标签栏，横屏和平板都一样；从 1200dp 起，消息列放在对话旁边。导航条用 [AppRail](../../packages/ui/src/components/app-rail/app-rail.md) 绘制，保留手机上的目的地和顺序，服务器标签除外：在那里，服务器是导航条头部的工作空间图块，是切换服务器的唯一入口，和网页一样（[导航](./navigation.md#the-server-in-the-apps-desktop-mode)）。保留每个平台各自的断点（网页 768px，App 840dp），不要强行统一：断点是布局的搭建方式，而导航的结构在哪里都一样，见[导航](./navigation.md#principles)。

```example
app-shell/compositions/responsive
```

### 频道的侧边列 {#the-channels-side-columns}

频道的 Thread、Tasks 和 Files 是一个个分区，由人放进对话右侧最多四列里，每一列是叠起来的若干分区。在有人移动它们之前，Thread 自己占一列，Tasks 叠在 Files 上面，在它右边。每一列在这一行里占满高度，左边是一条 `line-seam` 边线，平的，没有阴影；每列保持给它的宽度（起初 Thread 是 400px，另一列是 360px），这个宽度像右侧面板一样可以变宽（[间距](../foundations/spacing.md#resizing-columns)）。一列的最小宽度是其中最宽的分区的最小宽度：有 Thread 时 360px，没有时 280px。叠放的分区分享这一列的高度，每个至少 160px；在矮得放不下两个的列里，一次显示一个，上面是一行 Tasks / Files [标签页](../../packages/ui/src/components/tabs/tabs.md)。

这一行变窄时，按这个顺序让位：

1. 各列画窄，直到最小宽度，Thread 那一列最先：它先放弃记住的宽度，缩到 360px，其他东西才开始让位。记住的宽度不变，所以这一行变宽后会恢复。
2. 打开了消息列时，如果这一行放不下对话的 360px、360px 的 Thread 那一列和其他每一列的最小宽度，Thread 的整列，包括叠在里面的分区，就盖住对话，和专注模式一样（stdrc，2026-10-26，#proj-raft-ui:639854ff）。它占据对话的位置，填满其他列留下的空间；其他列留在它右边，在它的 360px 旁边能放下多少就放多少，最窄的先让出。它的标题栏显示 Back 而不是 ×（[导航](./navigation.md#closing)），Back 关闭消息列。盖住对话期间，什么都不能拖动，它那一列也没有宽度手柄。对话留在下面原处，隐藏起来，保留滚动位置和草稿；消息列关闭时，或者这一行比开始盖住时宽出 24px 时，对话原样回来，这样停在临界宽度上的窗口不会在两种状态之间闪动。因为自身的宽度（上表中不到 720px 的情况）而盖住对话的消息列，也会带上叠在它那一列里的分区。
3. 放不到盖住对话的 Thread 旁边的列，变成 Thread 那一列顶上的标签页：先是 Back，然后是 Thread 的标签，以及放不下的列里每个分区各一个标签，按布局里的顺序（[Tabs](../../packages/ui/src/components/tabs/tabs.md)：内容不同，所以用标签页）。选中的标签显示它的分区，分区保留自己的 ×（关闭的是这个分区，而不是盖住的状态；只有 Back 才退出盖住状态）。一列要比刚好放得下时多出 24px，才重新作为单独的一列回来，这样停在临界宽度上的一行不会在两种状态之间来回切换。
4. 没有打开消息列时，在对话旁边放不下的列浮在对话消息的右侧：最窄的先浮起（宽度相同时先浮最右边的），人最近一次移进单独一列的那个分区所在的列最后浮起。它们叠在同一个表面里，在对话的标题栏下方，紧贴面板的上边和右边，在消息输入框上方 12px，带 `float` 阴影，最宽 360px，且不超过面板的 58%；只要对话还能保留 520px（一列 280px 加 240px 的消息），就这样浮动。面板更窄时，以及在手机上，分区盖住面板标题栏下面的部分，包括消息输入框，在标签页下一次显示一个，并带 Back。

人拖动出来的列从不浮动，也从不盖住对话：只有在这一行容得下新布局的地方，才提供它的列边缘作为放置位置，必要时在放下时收起侧栏；否则拒绝放置，并在鼠标指针旁说明原因（[拖放](./drag-and-drop.md#refused-places)）。这些切换是瞬时的，没有动画（[动效](../foundations/motion.md#usage)）。

## 规则 {#rules}

### 按所在区域的宽度切换 {#switch-on-the-regions-width}

布局按它所在那一块的宽度切换，而不是窗口的宽度。同一个组件可能放在 1440px 窗口里一个 320px 的面板中，也可能铺满 390px 的手机：窗口宽度说明不了它有多少地方。资料面板、对话旁的消息列、弹窗、动态列表都比窗口窄；去问窗口的布局，仍会按一块它并没有的屏幕来排：360px 面板里出现两栏的列表，本该竖排的步骤行却折了行。

- **面板、栏、卡片里的内容，用那一块上的容器查询**：在那一块上加 `@container`，里面的东西用 `@sm:`、`@max-[…]:` 之类。自己切换布局的组件把自己设为容器，放到哪里都对；这样它会占满所在行的宽度，因为容器的宽度不能由里面的内容决定。所以要给它一个宽度确定的父元素：块级元素、被拉伸的 flex 或 grid 子项，或设了宽度的元素。放在按内容收缩的父元素里（`inline-block`、`w-fit` 或 `fit-content`、没设宽度的绝对定位框或浮层、`flex-basis: auto` 又没设宽度的 flex 子项），它会缩成零宽，文字一行一个词。把自己设为容器的组件会在各自的页面上写明这一点。
- **只有大小由窗口决定的东西才看窗口**：页面外框和它的断点（上表）、弹窗、底部弹层、toast、通知中心，以及面板头部在手机上的边距（手机上面板就是整页）。
- **鼠标还是触屏用 `pointer` 和 `hover` 判断，从不用宽度**（[触屏](#touch-screens)）：平板在 1024px 也是触屏，窄的桌面窗口照样有鼠标。
- **用脚本量出来的尺寸要一直量。** 观察当前挂着的那个元素（用 callback ref，不要在 effect 里只读一次 ref），它变大小、内容变了都重新量（在它上面挂 `ResizeObserver`；内容变化用 `MutationObserver` 或 layout effect：行内元素里的文字变了，`ResizeObserver` 不会报告）。只量一次的结果，在内容晚到、字体加载完或元素被换掉时就错了。
- **能不切换就不切换。** 会换行的一行、用 `auto-fill` 的网格、写成 `min(360px, 100%)` 而不是 `100vw` 减去对外框的估计的宽度：这些放在任何区域都合适，不用问它多宽。

2026-10 的梳理里，在窄区域里坏掉的布局有三种原因：按窗口宽度切换、只量一次、一行东西没有让位的办法。本节讲前两种，下一节讲第三种。

### 一行放不下时 {#when-a-row-runs-out-of-room}

每一行都要有让位的办法。工具栏、标题栏、筛选行或列表行必须在它所在区域能取到的最窄宽度下（Activity 的结果列表最窄到 320px）、用最长的译文和它可能装下的最长的值（邮箱地址中间没有可以断开的空格）时也放得下。放不下时，各部分按固定顺序让位，让人仍能看到每个控件：

1. 次要的文字按钮只显示图标，标签保留为无障碍名称和工具提示。Mark all read 变成 `check-check` 图标按钮。
2. 然后才轮到主控件只显示图标：分段控件的各段、标签页的标签。分段控件设了 `iconsOnlyBelow="auto"` 时自己这样做，正好在它的标签放不进给它的空间时：每段变成一个 32px 的方块，只有图标，标签保留为无障碍名称和工具提示（[SegmentedControl](../../packages/ui/src/components/segmented-control/segmented-control.md#behavior)）。
3. 一行控件仍然放不下时，折到第二行，控件保持完整；不能只显示图标的分段控件在自己的轨道里横向滚动，而不是溢出到旁边的控件上（[SegmentedControl](../../packages/ui/src/components/segmented-control/segmented-control.md#behavior)）。
4. 文字最后才截断，而且只截断名字或值（频道、人、邮箱、时间），从不截断控件的标签。

- 各部分不能重叠，控件也不能缩到比自己的内容还小：给控件包上 `min-w-0`，它的外框会缩小，内容却溢出到旁边的控件上。
- 每个能让位的部分都要给它让位的手段：可能被截断的文字加 `min-w-0` 和 `truncate`，一排控件加 `flex-wrap`，可能变窄的行里的分段控件设 `iconsOnlyBelow="auto"`。既不能缩、不能折行、也不能截断的那个部分，就是溢出的那个。
- 用这一行上的容器查询（`@container`、`@max-[…]:`）决定何时切换，而不是窗口宽度（[按所在区域的宽度切换](#switch-on-the-regions-width)）。如果要切换的是某个部分的内容放不放得下，就去量内容，而不是猜一个宽度，像 `iconsOnlyBelow="auto"` 那样：按一种语言或一个数量挑出来的宽度，换一种就不对了。
- 不要为了放下一行而缩小文字或控件高度：小到读不清的标签、小到点不中的目标，比带工具提示的图标更糟。

### 第一帧就是稳定下来的样子 {#the-first-frame-is-the-settled-one}

第一帧就按它之后会保持的样子画。用「还不知道」的默认值画出一帧、过一会儿再修正，就是一次闪动：一行变宽又缩回去，一个面板以一个宽度打开又跳到另一个宽度，一张卡片突然出现、把页面往下推。在那一刻，人看到的是一个本不该出现的布局，控件还在鼠标指针下面移动。

- **在第一次绘制之前读出决定布局的东西。** 记住的宽度、收起的区块和视图模式从存储里读进初始状态；视口、指针类型和平台也一样。不要在挂载后的 effect 里读它们：effect 在浏览器绘制之后才运行。
- **在 layout effect 里测量，并在那里做决定**，而不是在下一个动画帧里：在 layout effect 里设置的状态，会在浏览器绘制之前重新渲染。只有之后的测量（比如尺寸变化时）才等一帧。
- **数据重新加载时，保持一个部分的有无和大小。** 列表因为换了筛选而重新加载时，计数，以及只在有计数时才显示的控件，都保持上一次的值，直到新的结果到来。不要把它们降成空的默认值再恢复。在那一刻消失的控件会把它的空间让给旁边的部分，它们就会重新排一遍：设了 `iconsOnlyBelow="auto"` 的分段控件会先显示标签，然后又变回图标。
- **占位占据它所代表的东西的大小和位置。** 代码懒加载的面板，它的 fallback 是这个面板自己的框，用记住的宽度，而不是这一行剩下的空间。骨架屏和它的内容一样大（[反馈](./feedback.md#empty-loading-and-failed)）。
- **真正的结果到来时，只变一次：** 从旧值直接变成新值，从不经过一个空值。

### 触屏 {#touch-screens}

触屏没有悬停，所以只在悬停时出现的东西在触屏上够不到。按输入方式判断，而不是按宽度：用 `pointer: coarse` 媒体查询，因为横放的平板是触屏，而窄的桌面窗口仍然用鼠标。

- 用鼠标时，一行的操作只在悬停时出现，Activity 行上的 Mark as Done 也一样：在这一行被悬停、拥有键盘焦点或从它打开了菜单时显示，静止时隐藏。每一行都显示按钮的列表读起来像一堵按钮墙，会把视线从内容上拉走；而且鼠标要点的本来就是这一行。隐藏的操作仍在 Tab 顺序里。
- 在触屏上，如果悬停操作是这一行的主操作，静止时也显示：在行尾放一个 44px 的目标，带图标。行的其余部分给它让出位置，而不是垫在它下面（[InboxItem](../../packages/ui/src/components/inbox-item/inbox-item.md#behavior)）。
- 在手机上，Activity 行上的 Mark as Done 是例外：要左滑这一行或通过它的长按菜单才能用到，静止时没有按钮（stdrc，2026-10-23）。一个大多是待清理的行的列表，每行一个按钮，读起来就是一列按钮；而在手机上，人本来就是把一行滑走来清理列表的（Mail、Messages）。平板和桌面端保留这个按钮：那里的行更宽，滑动也不是习惯。
- 每个悬停操作也放进这一行的长按菜单里，就是桌面端右键打开的那个菜单，这样每个操作在每种设备上都只在一个地方（[对话](./conversation.md)）。
- 滑动可以作为这一行各个操作的快捷方式（左滑把它们作为按钮露出来，并弹出带 Undo 的轻提示），但不能是唯一的入口：长按菜单里有同样的操作（[无障碍](../foundations/accessibility.md)）。
- 只有手指明显横向移动时，才开始滑动一行：横向距离是上下距离的两倍以上，并且超过平台的触摸容差（touch slop）。拖动开始后变成竖向的，就回到滚动列表。否则人在滚动列表时会不小心滑动其中的行。
- 在超过平台的触摸容差之后再做这个判断；网页没有触摸容差，用 10px，所以「两倍」这条规则在手指移动了 20px 时判断。从屏幕左右边缘 24px 以内开始的滑动留给浏览器和系统，它们的返回和切换应用手势从那里开始。
- 左滑在行尾露出这一行的操作按钮，再点其中一个，和 iOS Mail 一样（stdrc，2026-10-23）。松手时超过按钮宽度的一半，或者超过容差后向左快速一划，这一行就停在打开的状态；不到一半，或者向回一划，它就弹回去。只有距离会执行 Done，快速一划从不会，所以快速滑动不会不小心完成一行。拉过行宽的 60% 后松手，立即执行第一个操作 Done：最常用的操作仍然只要一个手势。一次只打开一行：点别的任何地方、滚动列表、把这一行滑回去或打开另一行，都会关上它。有一行打开时，在列表里点一下只会关上它，和 iOS Mail 一样；在列表外点一下（轻提示的 Undo、标签栏），会关上它，并执行所点的东西本来的操作。
- 按钮画在行尾，主操作在最外侧：先是 Done，然后向内是这一行的其他操作（Unfollow、Mute），每个 72px 宽、和行一样高，18px 的图标在上，下面是一个 `text-caption`、字重 600 的词：彩色填充上的一个短词必须一眼就能读出来。Done 是实色 `success` 配墨色；其他按钮是 `fill-muted` 配 `foreground`，这样只有一个操作突出，其余保持安静。超过 60% 的位置后，Done 按钮变宽，盖过其他按钮，占满整个露出的宽度，在 Android 上手机轻震一次（10ms 振动，浏览器支持时）；退回到这个位置以内，按钮恢复原样。下拉刷新用同样的方式显示触发和解除，包括轻震（[导航](./navigation.md#refreshing)）：手指松开之前必须知道结果。按钮上的词是操作最短的名字（「Done」「Unfollow」「Mute」），因为按钮很小；菜单项保留完整的名字（「Mark as Done」）。图标就是这个操作在这一行菜单里的图标（Done 是 `check`，Unfollow 是 `message-circle-off`，Mute 是 `bell-off`），这样两个按钮永远不会看起来像同一个操作，菜单也就教会了人怎么滑。
- 操作把这一行移出列表时（Done、Unfollow），立即移出，并在轻提示里给一个 Undo，这样的轻提示保留 8 秒（[Toast](../../packages/ui/src/components/toast/toast.md)）。有确切反操作的操作立即执行，Undo 执行它的反操作（Unfollow 和 Follow，Mute 和 Unmute），和这一行的菜单一样。Done 没有反操作，所以它等着轻提示：轻提示关闭时、另一行的操作被执行时（那一行的轻提示取代这一条），或者离开列表、页面被隐藏时，它才执行；如果这期间这一行有了新动态，就放弃执行。Undo 把这一行放回原来的位置。Mute 把这一行留在列表里，标为已静音，轻提示和 Undo 都一样；已静音的行的按钮里没有 Mute。
- 处理这一行的操作（上面那些）都用左滑，全放在一侧：三个操作分到两个方向上不好分（stdrc，2026-10-23）。这类操作只有 Done 的行，就只显示这一个按钮。右滑留给唯一一个只改变这一行已读与否的操作，和 iOS Mail 一样：未读的行上是 Mark as read，已读的行上是 Mark as unread（artin 和 stdrc，2026-10-24）。它是行首的一个按钮，用菜单项的图标（`message-square-check`、`message-square-dot`），下面是它最短的词（「Read」「Unread」），用 `fill-muted` 配 `foreground`，距离也和左滑一样：超过它宽度的一半就停在打开状态，拉过 60% 就执行。这一行留在原处，所以没有轻提示，也没有 Undo：再滑一次就切换回去。在 Unread 或 Mentions 筛选下，刚标为已读的行仍然留着，直到人离开列表或换了筛选，和邮件客户端一样，这样往回滑时总有一行可滑。屏幕左边缘的 24px 仍然留给系统的返回手势。
- 在触屏上，次要的悬停操作不放在行里；它们放在菜单里，让列表保持安静。

### 手机 {#phone}

- 按 390px 宽设计，并保证在 320px 下所有东西都放得下，这是仍在使用的最窄的手机。
- 长名字截断。长值在表单输入框里怎么处理、哪些内容改为换行，见[表单](./forms.md#long-values-in-fields)。
- 按钮可以换到新的一行。不要缩小按钮文字：小到读不清的标签比高一点的按钮更糟。
- 分段控件最多 4 段。放不下时只显示图标，标签保留为无障碍名称（`iconsOnlyBelow="auto"`）。
- 标签页放不下时横向滚动（[Tabs](../../packages/ui/src/components/tabs/tabs.md)）。
- 触屏上的消息输入框和消息操作，见[对话](./conversation.md#the-composer)。
