# 标题栏

标题栏属于窗口，不属于内容。它说明这是哪个窗口，让人移动它，放窗口自己的按钮，再放少数几个作用于整个窗口的命令。凡是作用于窗口里显示的东西（一份文档、一段对话、一个列表）的操作，都属于那块内容自己的头部或工具栏，在标题栏下面。把内容的控件搬进标题栏，一行里就有了两套尺寸、两套规矩，旁边还挨着系统按钮，看起来就是两样东西拼在一起（xxchan，2026-11-20，#proj-workspace:c3673fa1）。

每个平台、每个做得好的桌面应用都按自己的方式遵守这条规则，见文末的[参考](#references)。

## 适用范围 {#when-it-applies}

- Raft 桌面应用的每一种窗口：主窗口、在独立窗口里打开的对象（从「在新窗口中打开」打开的 Artifact），以及盖满整个窗口的层（文件或图片预览、分享预览、全屏的图表）。
- 不包括在浏览器标签页里的网页版：那里的标题栏由浏览器画。网页版的顶栏和主窗口的标题栏是同一条（[页面结构](./page-structure.md#the-web-top-bar)），所以下面关于它里面放什么的规则对它同样适用。

## 标题栏是干什么的 {#what-a-title-bar-is-for}

标题栏有四件事，按这个顺序：

1. **说明这是哪个窗口。** 显示的是什么，在 Raft 里还有属于哪个服务器。标题写内容的名字，不写应用名（写「QA long page」，不写「Raft」）。
2. **移动窗口。** 任何宽度下都留出能拖的空白。拖动、双击最大化、右键打开系统菜单，都在这块空白上。
3. **放窗口自己的按钮。** 系统的按钮：macOS 的红绿灯，Windows 和 Linux 的窗口按钮。它们不被遮挡、不挪位置、不重画。
4. **放少数几个作用于整个窗口的命令。** 在地方之间移动（后退、前进），在任何地方找东西（搜索），切换窗口显示什么（工作区），或者调整窗口布局（显示或隐藏一栏）。最多几个，好让拖动区和标题留得住。

其余的都是内容：它作用于窗口里的东西，所以放在那个东西的头部或工具栏里。

| 放在标题栏 | 不放在标题栏 |
| --- | --- |
| 对象或工作区的名字、图标，属于哪个服务器 | 版本选择、状态、数量 |
| 后退、前进、历史 | 评论模式、编辑、格式 |
| 在整个服务器里搜索 | 在这份文档里搜索 |
| 显示或隐藏这个窗口的一栏 | 分享、复制链接、下载这个对象 |
| 更新按钮、谁在工作、铃铛 | 对象自己的 ⋯ 菜单 |
| 系统的窗口按钮 | 仿制的窗口按钮 |

## 规则 {#rules}

- 标题栏是框架上的一行，在框架的底色上（`layer-frame`，服务器的主题），下面一条 `line-seam`。里面的控件是框架项（`variant="on-frame"`，[Button](../../packages/ui/src/components/button/button.md)）。
- 内容自己的头部或工具栏紧贴在标题栏下面，在画布上，绝不放进标题栏。两者从不合成一行。
- 系统按钮保持原生，用标题栏的颜色和高度；它们那个角里不画、不放、不弹出任何东西（`--raft-frame-inset-start`、`--raft-frame-inset-end`、`--raft-frame-inset-top`，[页面结构](./page-structure.md#the-web-top-bar)）。
- 始终留出拖动区。整条栏标为可拖动，里面每个控件标为不可拖动。窗口变窄时，先用省略号截断标题，再把窗口级命令收进菜单；系统按钮永远不收。
- 保留系统行为：双击最大化（macOS 上是缩放），Windows 和 Linux 上右键打开系统菜单，窗口不是当前窗口时标题栏变暗。
- 不在标题栏里重复窗口按钮已经做的事：系统的关闭旁边不再放内容的关闭或展开。

## Raft 的窗口 {#rafts-windows}

### 主窗口 {#the-main-window}

标题栏就是网页顶栏：工作区按钮和工作区条，后退、前进和历史，中间是搜索，然后是更新按钮、谁在工作和铃铛（[Raft Chat](../products/raft-chat/README.md#the-desktop-app)）。这里每一项都作用于整个窗口，已经符合这些规则。下面的面板（对话、讨论串、侧面板）保留各自的头部。

### 在独立窗口里打开的对象 {#an-object-in-its-own-window}

在独立窗口里打开的对象（Artifact）是同一个服务器的窗口，所以和主窗口一样分两层：框架上的标题栏，下面画布上是对象的头部。

- **标题栏**，36px，在服务器主题的 `layer-frame` 上，可拖动：对象的图标贴片（`IconTile` `sm`）和标题，然后是系统按钮。别的都没有。主题的框架色就是这个窗口说明自己属于哪个服务器的方式，和主窗口的框架一样。
- **对象的工具栏**，头部高度（`header-height`），在画布上：主窗口里面板头部放的东西（版本、评论模式、在文档里搜索、分享、⋯、评论栏开关），用面板头部的尺寸（[Panel](../../packages/ui/src/components/panel/panel.md#rules)）。没有关闭和展开：窗口自己的按钮做这件事。
- **窗口外缘。** 小窗压在主窗口上时，它的上边缘不能和主窗口的框架连成一片（两条同样主题色的栏接在一起）。macOS 和 Windows 11 会给每个窗口画边框、圆角和阴影，那里什么都不加，再加一条就成了双线。Linux 和 Windows 10 不画，给窗口加一圈 1px `line-seam`。窗口按钮区由系统从窗口最顶上盖在网页上画，所以上边线画到按钮区左边为止；按钮那一段由按钮区自己的底色把窗口区分开。
- 窗口里的区域保留自己的头部：评论栏保留排序和「隐藏评论」（[评论](./comments.md)）。

标题栏让窗口少了 36px 高度。这是把窗口的控件和对象的控件分开的代价；把它们重新合成一行，正是让这一行看着割裂的原因。

### 盖满整个窗口的层 {#a-layer-that-covers-the-whole-window}

文件或图片预览、分享预览、全屏的图表：打开时这个层自己的头部就是标题栏。它写明显示的是什么，放关闭和最多两个作用于它的操作；空白处可以拖动窗口，并且避开系统按钮。比窗口窄的层，比如侧面板或对话框，则从标题栏下面开始（[Raft Chat](../products/raft-chat/README.md#the-desktop-app)）。

## 平台 {#platforms}

| | macOS | Windows | Linux |
| --- | --- | --- | --- |
| 窗口按钮 | 红绿灯在开头，14px，系统画 | 窗口按钮在末尾，系统画（`titleBarOverlay`） | 窗口按钮在末尾，Electron 按 GTK 画（圆形，按标题栏的颜色着色） |
| 要留的位置 | 标题栏的内容从左边 82px 处开始（红绿灯和它后面的空隙），不再另加内边距；全屏时从页边开始 | 末尾留出窗口按钮的宽度 | 末尾留出窗口按钮的宽度 |
| 标题栏最矮 | 约 28px（放得下红绿灯） | 约 32px（再矮会把按钮压扁；Raft 最少允许 24px） | 约 32px |
| 窗口按钮的颜色 | 系统自己的 | 按标题栏的底色和 `foreground-on-frame` 设置 | 按标题栏的底色和 `foreground-on-frame` 设置 |

红绿灯居中在标题栏这一行上：它的 y 跟着标题栏高度变（44px 时 15，40px 时 13，36px 时 11）。

## 参考 {#references}

2026-11-20 查阅。各家都同意上面的四件事，区别在允许放多少个窗口级命令。

- **macOS（Apple HIG，Windows 和 Toolbars）。** 框架里是窗口按钮和一条在标题栏下面或与之合并的工具栏。标题写内容的名字，不写应用名，而且要短。工具栏里的每个命令在菜单栏里也有。
- **Windows 11（Fluent，Title bar）。** 图标、标题和窗口按钮；可选开头的后退、居中的搜索和末尾的账户，这些会让标题栏从 32px 变成 48px。所有空白都能拖。图标和窗口按钮始终完整可见；标题栏里的控件要声明为穿透区域。
- **GNOME（HIG，Header bars）。** 主要操作在开头，窗口标题或视图切换在中间，菜单在末尾；控件不多；总要留一些能拖的空白。
- **VS Code（自定义标题栏）。** 菜单、命令中心（后退、前进、居中的搜索）和布局开关。编辑器的标签、编辑器的操作和状态栏都不在里面；右键标题栏可以选显示哪些项。
- **Chrome 应用窗口（Window Controls Overlay）。** 标题栏缩到只剩系统按钮，其余由应用自己画；应用必须标出拖动区，并且不能让自己的内容看起来像浏览器自己的文字。
- **Arc 的 Little Arc。** 一个只用来快速看一眼的小窗：一条窄栏，有网页的域名和「Open in」，没有主窗口的侧栏和标签。要留下或继续处理，就把它移到主窗口。
