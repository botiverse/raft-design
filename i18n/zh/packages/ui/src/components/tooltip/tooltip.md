# Tooltip

工具提示（Tooltip）是在悬停、键盘聚焦时，或者在触屏上长按时出现的一行文字，给没有可见标签的东西说明名称、后果或键盘快捷键。图标按钮、被截断的名字、运行时标签片和桌面端导航条上的各项都用它。

## 何时使用 {#when-to-use}

| 情况                                                                     | 用                                                                                    |
| ----------------------------------------------------------------------------- | -------------------------------------------------------------------------------------- |
| 图标按钮、被截断的名字、运行时标签片（"Runs on Martin's MacBook"） | Tooltip                                                                                |
| 桌面端导航条上的一项                                                   | 右侧的 Tooltip，写目的地的名称（[AppRail](../app-rail/app-rail.md)） |
| 控件上已经能看到的标签                                | 不用：不要在工具提示里重复它                                  |
| 带链接或按钮的内容                                               | [Popover](../popover/popover.md)                                                       |
| 一个人或一个 Agent                                                          | [PreviewCard](../preview-card/preview-card.md)                                         |

## 结构 {#anatomy}

- `TooltipProvider`：为其中的工具提示设置打开延迟。在 raft-ui 里它们没有延迟，立即打开。
- `Tooltip`：根元素。必需。
- `TooltipTrigger`：工具提示所描述的元素。必需。`openOnLongPress` 和 `openOnTap` 决定它在触屏上怎样打开（[触屏](#touch-screens)）。
- `TooltipContent`：工具提示本身，带一个指向触发元素的小箭头。里面可以放一个前置图标和一个表示快捷键的 `Kbd`。必需。
- `TooltipPortal`：一个更底层的部件。

工具提示用 `layer-hud`，文字用 `foreground-on-hud`，和轻提示（Toast）一样（[颜色](../../../../../design/foundations/color.md#surfaces)）。

## 行为 {#behavior}

- 它在触发元素上方打开，水平居中；上方没有空间时翻到下方。
- 在手机上的底部面板或抽屉里，正文中控件的工具提示留在面板头部下方；头部按钮上的工具提示照常在按钮上方打开（[Dialog](../dialog/dialog.md#popups-in-a-sheet)）。
- 上方的空间到窗口自己的控件为止。桌面端外壳在页面顶部之上绘制标题栏按钮时，会在根元素上把这条带的高度设为 `--raft-frame-inset-top`；会打开到这条带里的工具提示翻到下方，在触发元素旁边的则向下移出这条带。Web 端不设置它。
- 触发元素在这条带里时，碰到 `--raft-frame-inset-start` 和 `--raft-frame-inset-end` 也一样往反方向弹。它们是这条带的两个角（macOS 的红绿灯按钮、Windows 的标题栏按钮），不是竖列：在这条带下面，它们不限制任何东西（[页面结构](../../../../../design/patterns/page-structure.md#frame-insets)）。
- `side="right"` 把它放在触发元素旁边，如在导航条上；`side="bottom"` 把它放在触发元素下方。
- 它在 20rem 处换行，或者在窗口剩余空间处换行。
- 鼠标指针离开、焦点离开或按 Esc 时关闭。

### 触屏 {#touch-screens}

触屏没有悬停，所以在触屏上，工具提示在长按时打开，和移动端 App 的工具提示一样。没有这一点，禁用按钮的原因（能让它可用的那一步）在手机上就看不到；有了它，这个原因在网页和 App 里的每个屏幕上都以同样的方式送达。

- 手指静止按住触发元素 500ms 就打开工具提示：这是设计系统的长按，也就是长按菜单打开、触屏拖动就绪的那一刻（[触屏上的拖动](../../../../../design/foundations/states.md#dragging-on-a-touch-screen)）。按住不会按下触发元素：抬起手指不执行任何操作。
- 它在禁用的按钮上也会打开，所以禁用按钮的原因用触屏也能看到。按钮仍然必须能接收触摸：给它 `focusableWhenDisabled`（`aria-disabled`），带原因的禁用按钮本来就有这一项（[Button](../button/button.md#accessibility)）。原生 `disabled` 的按钮不接收触摸，它的工具提示永远不会打开。
- 在 500ms 到之前移动超过 10px 的手指是在滚动，什么都不打开；滑过一排触发元素从不会打开它们的工具提示。
- 按住之后，手指按着时工具提示一直显示，抬起 1.5 秒后关闭，留出时间读刚才被手指挡住的那行字。点按别的任何地方会立即关闭它。
- 短暂的点按照常按下触发元素，什么都不打开。
- 长按属于拥有它的那一层；只有别的东西都不要它时，工具提示才接手。所以默认情况下，在这些地方按住什么都不打开：
  - 链接上：链接自己的长按会给出系统菜单（复制链接、在新标签页中打开），比工具提示更有用，而且链接的名称就在它的无障碍名称里；
  - 长按所有者里面：即标有 `data-long-press-owner` 的元素。raft-ui 给自己的这类元素加了标记：`ContextMenuTrigger`、可以重新排序的标签页、消息输入框里可以排序的附件、可以拖动的任务。应用给运行自己长按的元素加上标记（带触屏菜单的消息行、可排序的项）：在那里按住是它的菜单或它的拖动，从不两样同时发生。
- 在所有者里面，原因必须照样显示的禁用按钮用 `openOnLongPress` 把按住拿回来：它的工具提示打开，所有者的菜单或拖动不会开始。触发元素带有 `data-tooltip-long-press`，触摸到它就不再往上传，所以通过 React 监听的所有者（`ContextMenuTrigger`）永远不会就绪；有自己 DOM 监听器的所有者，跳过从 `[data-tooltip-long-press]` 里面开始的触摸。`openOnLongPress={false}` 在其他任何地方关掉按住。
- 每个触发元素都是 `select-none`，所以按住一个名字不会选中它的文字。
- 只为说明而存在的按钮（设置旁边的 ⓘ）用 `openOnTap` 在点按时打开，下一次点按（点它或别的任何地方）关闭它。它的点按不做别的事，所以要按住才打开只会让它更慢。它的点击不再关闭工具提示。

## 内容 {#content}

- 写一个名称或一句短句，用 sentence case：Search、Runs on Martin's MacBook。
- 工具提示里的用词与触发元素的 `aria-label` 相同。
- 快捷键放在文字后面，一键一帽：用键名写的 `sm` 的 `KbdShortcut`，在 Mac 上画成 ⌘ K，其他系统画成 Ctrl K（[Kbd](../kbd/kbd.md)）。
- 禁用控件的工具提示还要说明怎样才能用上它（读者能做的那一步，或者谁能做；不写 Raft 的内部原因，见[写作](../../../../../design/content/writing.md#principles)），并且第一行是控件的名字（触发元素上它的标签被截短了）时，把这一步放在第二行，用 `foreground-on-hud-muted`，在名字下方 4px：先是名字，再是那一步。只有这一步时，它就是工具提示唯一的一行，用工具提示自己的文字颜色。

## 无障碍 {#accessibility}

- Tooltip 封装了 Base UI 的 Tooltip。它提供 `tooltip` 角色，在悬停、键盘聚焦时打开，在触屏上长按时打开（[触屏](#touch-screens)）。
- 工具提示是对名称的补充，不能代替名称。每个只有图标的按钮都要有自己的 `aria-label`。
- 触屏没有悬停。工具提示在那里长按时打开，而人只有在找它时才会发现：工具提示只放有帮助但不是必需的内容（名称、禁用按钮的那一步）。每个人都必须读到的内容放进界面里。
- 行按钮里的标签上的工具提示，只有鼠标够得着。把它那句话作为视觉隐藏文字放进标签里，让它成为行的名称的一部分，工具提示保留作为补充（[无障碍](../../../../../design/foundations/accessibility.md#focus-and-keyboard)）。

## 规则 {#rules}

- 不要在工具提示里放链接、按钮或任何需要人去操作的东西：鼠标指针够不着它。
