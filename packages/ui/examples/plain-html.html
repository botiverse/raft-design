02 / Coverage boundary

这份结论覆盖什么

覆盖边界先于细节表。读者在相信结论之前，先看清它不能代表什么。

Observed

冷 / 暖各 10 次；production Vite build/preview；real repo PGlite seed；Chromium CDP。

Observed

150 条 seed 消息；初次加载最新 50 条；100 ms latency / 20 Mbps down。

Not measured

真实生产数据库、公共 staging 地理位置、不同网络地区或设备分布。

Not claimed

这些数字不代表当前生产；也不证明 renderer 可以忽略。

Counter-signals

  • 冷缓存 UI tail 仍有 191.1 ms。
  • 冷缓存 max-long-task p95 达 242.0 ms。
  • 暖缓存会重置内存状态，但不会消除 fresh API work。

04 / Status + reason + next action

下一步如何闭合

Owner

Performance lane

把 messages 请求拆成 server work、transfer 与 client parse/commit；保留同一 seed、网络模型和 cold/warm 定义。

Lift condition

同一 head 上复现至少 10+10 次，并让新 instrument 能分别回答：请求为何慢、响应后为何仍有 171-191 ms。未满足前，状态保持 FOCUS，不写成已修复。

05 / Audit layer

方法与回单

默认折叠，但不是删掉。摘要必须自足，审计者仍可继续下钻。

测量方法与 percentile policy
  • 链路：loadUser -> loadServers -> ServerResolver/setCurrent -> MainLayout + parallel sidebar bootstrap -> ChannelById -> loadMessages -> first seeded message visible。
  • p50 是中位数；偶数样本取中间两项平均。
  • p95 使用 nearest-rank，因此 n=10 时 p95 是该组最大值。
  • DOM probe 采样 mutations 与 animation frames；常规里程碑精度约一个 frame。
